# Introduction

Qu (pronounced "queue") is a specification-first scripting language for people
whose work is *numbers over time*: acquiring a signal, cleaning it into a
table, fitting a model, and turning the result into a figure — often an
animated one. It blends the readability of BASIC and MATLAB, the array
discipline of FORTRAN, the ecosystem thinking of Python and R, and a
declarative approach to plotting. Above all it aims to read like mathematics
and science, not like a program.

Qu 0.12 is a written language definition with a growing reference
implementation. This book is the human-readable companion to the canonical
specification (`docs/qu-language-spec.md` in the repository) and to the
reference interpreter under `engine/crates/qu-interp`.

## Who this book is for

- **Scientists and engineers** coming from MATLAB or NumPy/Python who want a
  readable scripting surface for signals, matrices, and quick plots, without
  giving up correctness or reproducibility.
- **DSP and ML practitioners** who need filters, transforms, fitted-model
  protocols (`fit`/`predict`/`score`), and estimation-theory primitives
  (Kalman/EKF/UKF/particle filters) in one language.
- **Contributors to Qu itself**, who want a map of what the standard library
  actually contains today, generated from the interpreter's own builtin
  dispatch rather than aspirational prose.

## How this book is organized

1. **[Getting Started](getting-started/quickstart.md)** — a one-chapter
   **Quickstart** tour (install, first script, one runnable example per
   domain) for anyone who wants a working feel for Qu in a few minutes,
   followed by three books, in order, teaching the language itself in
   depth, then numerics/DSP/linear algebra, then specialized domains
   (circuits, ML, distributed execution). Every runnable snippet has been
   checked against the reference interpreter.
2. **[Language Reference](language-reference/spec.md)** — the full language
   specification: lexical elements, type system, control flow, functions,
   the plotting sublanguage, diagnostics, and the implementation roadmap.
3. **Standard Library Reference** — a function-by-function reference,
   organized by domain (core math, signal processing, statistics/ML,
   plotting, images, collections, file I/O, concurrency, REPL). Each chapter
   is a table generated by surveying the interpreter's own builtin dispatch
   table (`engine/crates/qu-interp/src/lib.rs`), so it reflects what actually
   runs today rather than what is merely planned.
4. **[Playground](playground.md)** — a pointer to the browser-based
   interactive playground, which lives outside this book.

## Implementation status

Qu is implemented in milestones (see `IMPL.md` and `BACKLOG.md` in the
repository root for the day-to-day log). This book describes only what runs. A
feature the specification designs but the engine does not have yet is
absent here rather than marked: a tutorial that teaches something which
fails to parse is worse than one that is shorter. The specification is the
forward-looking document and says so; the
[builtin index](stdlib/builtin-index.md), generated from the interpreter's
own name table, is the authority on what exists today. If prose and grammar
ever disagree, treat it as a specification defect, not a reason to guess.

## A note on other documentation in this repository

The `docs/` directory also contains a browser-based interactive playground
(`docs/ide.html`, `docs/app.html`) and several standalone HTML reference
pages (`functions.html`, `data-ml.html`, `notation.html`, and others). Those
are deliberately kept separate from this book — the playground is a live
runtime, not documentation — and are cross-linked from here where relevant
rather than absorbed into it.
