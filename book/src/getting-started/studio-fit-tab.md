# The Fit tab: curve fitting and equation solving

The **Fit** tab of Qu Studio is a front end to ordinary Qu code, like the DSP
filter designer and the Loop tab: whatever you click is translated into one
readable script that you can see, copy, open in the editor, edit and re-run.
The panel never computes anything itself; it runs the script and draws the
vectors the script leaves behind. It has two modes, switched at the top:
**Fit** and **Solve equations**.

## Fit mode

1. **Pick the data shape.** `y(x)` (two columns), `z(x, y)` (a surface over two
   inputs) or *signals over time* (several columns against a time column).
2. **Load data.** A built-in example (generated by seeded Qu code, so it is
   the same every time), pasted text or CSV (commas, tabs, semicolons or
   spaces, with or without a header; bad cells are reported, not hidden), a CSV
   file from disk, or numeric variables left by the last Code run. A preview
   shows the first rows with the count, range and mean of each column. Up to
   200 rows are written into the script as a literal; larger tables are read
   with `read_csv` from a file.
3. **Pick a model**, press **Fit**. Starting values are worked out from the
   data by lines of Qu that you can read and edit (the *data summary* names
   such as `cf_ypk`, the height of the biggest excursion), so the first click
   normally converges.

Models for `y(x)` and for each signal over time: polynomial of degree n (starts
from `polyfit`), line through the origin, exponential decay or growth (with and
without offset), power law, logarithmic, logistic, sigmoid with baseline,
Gaussian peak (with and without baseline), Lorentzian, sum of two exponentials,
sine (starting frequency and phase from an FFT), rational, Michaelis-Menten,
Arrhenius, Hill, and **custom**: type `a*exp(-b*x)+c` and every name that is
not `x`, `pi`, `e` or a math function becomes a parameter. For surfaces: plane,
polynomial surface of degree n, 2-D Gaussian, and a custom expression in `x`,
`y` and parameters.

Everything is `least_squares` (Levenberg-Marquardt) on a residual function the
script spells out. That gives, for every fit, the parameter values, standard
errors, 95 % confidence intervals, t and p values, and a `converged` flag. The
standard errors are `cov = s^2 (J'J)^-1` at the solution, linearised: exact for
models linear in their parameters and an approximation otherwise; the panel says
so next to the table. Goodness of fit: R2, adjusted R2, RMSE, sigma-hat,
reduced chi-square (when y errors are given), AIC, AICc and BIC, and a residual
summary (mean, standard deviation, skewness, kurtosis, a Jarque-Bera normality
hint and the lag-1 autocorrelation).

Options: **weights** (a y-error column, giving weights 1/sigma, or a weight
column); **robust fitting** by iteratively reweighted least squares with Huber
or bisquare weights, written out as a loop in the script; **bounds** (passed as
`lower=` / `upper=` and enforced by clamping each trial point; a parameter that
sits on its bound is flagged because its standard error is not valid there);
**fixed parameters** (held at their start value); **multi-start** (the guess
scaled by fixed factors, lowest cost kept); a **95 % confidence band** of the
curve (delta method with central differences); an **extrapolation** range; and
log-x / log-y axes for display.

**Compare models** fits several models to the same data in one script and
ranks them by AIC, AICc or BIC with Akaike weights and the overlaid curves. A
model that fails to fit or does not converge is listed as such, not dropped. A
difference under 2 in the criterion means the data cannot tell two models apart.

**Signals over time.** Tick the signal columns. Fit each one separately,
**jointly with shared parameters** (one residual vector over all signals, for
example a common decay rate with separate amplitudes), or as an **ODE**
`y' = f(t, y)` per signal: type the right-hand side (`-k*y`, `r*y*(1-y/K)`) and
the residual function integrates it with `ode45` at the sample times, fitting
the parameters and optionally the initial value. With two or three signals a
trajectory view plots one against the other (and a 3-D view for three).

**Surfaces** are drawn as a contour or 3-D surface with the data points, with a
residual-versus-fitted plot and a residual map.

Plots are drawn by the Studio plot viewer from the vectors the script leaves
behind (`cf_gx`, `cf_gy`, `cf_res` ...), the same way as the Filter Designer.
**Edit the code** detaches the panel from its settings: Fit then runs your text
and reads the same variable names.

### A worked example

The built-in *Exponential decay with noise* example fitted with the
*exponential decay / growth* model produces this script. It runs as it stands:

```qu
# Curve fit: y = f(x), exponential decay / growth
# Generated by the Fit tab: every number below comes from this script. Edit and re-run it freely.
# built-in example: Exponential decay with noise (y = 3 exp(-0.5 x) + 0.4 plus noise (sigma 0.05))
seed(7)
x = linspace(0, 10, 40)
y = 3 * exp(-0.5 * x) + 0.4 + 0.05 * randn(40)
sg = 0.05 * ones(40)

# ---- exponential decay / growth: a * exp(-b * x) + c ----
cf_x0 = min(x)
cf_x1 = max(x)
cf_xr = cf_x1 - cf_x0
cf_y0 = y[argmin(x)]
cf_y1 = y[argmax(x)]
cf_ym = median(y)
function cf_model(x, a, b, c)
  return a * exp(-b * x) + c
end function
function cf_eval(x, q)
  return cf_model(x, q[0], q[1], q[2])
end function
function cf_resid(q)
  return (cf_eval(x, q) - y)
end function
cf_eb = 3 / cf_xr
if abs(cf_ym - cf_y1) > abs(cf_ym - cf_y0) then
  cf_eb = -cf_eb
end if
cf_ea = (cf_y1 - cf_y0) / (exp(-cf_eb * cf_x1) - exp(-cf_eb * cf_x0))
cf_ec = cf_y0 - cf_ea * exp(-cf_eb * cf_x0)
cf_q0 = [cf_ea, cf_eb, cf_ec]   # starting values of a, b, c
cf_fit = least_squares("cf_resid", cf_q0, max_iter=500)
cf_q = cf_fit.params
cf_se = cf_fit.stderr
cf_lo = cf_fit.ci[:, 0]
cf_hi = cf_fit.ci[:, 1]
cf_tv = cf_fit.t
cf_pv = cf_fit.p_values
cf_pred = cf_eval(x, cf_q)
cf_n = length(y)
cf_k = length(cf_q)
cf_res = y - cf_pred
cf_dof = cf_n - cf_k
cf_ssr = sum(cf_res .^ 2)
cf_sst = sum((y - mean(y)) .^ 2)
cf_r2 = 1 - cf_ssr / cf_sst
cf_r2adj = 1 - (1 - cf_r2) * (cf_n - 1) / cf_dof
cf_rmse = sqrt(sum(cf_res .^ 2) / cf_n)
cf_sigma = sqrt(cf_ssr / cf_dof)
cf_chi2 = cf_ssr / cf_dof
cf_aic = cf_n * log(max(cf_ssr, 1e-300) / cf_n) + 2 * cf_k
cf_aicc = cf_aic + 2 * cf_k * (cf_k + 1) / (cf_n - cf_k - 1)
cf_bic = cf_n * log(max(cf_ssr, 1e-300) / cf_n) + cf_k * log(cf_n)
cf_rc = cf_res - mean(cf_res)
cf_m2 = mean(cf_rc .^ 2)
cf_skew = mean(cf_rc .^ 3) / cf_m2 ^ 1.5
cf_kurt = mean(cf_rc .^ 4) / cf_m2 ^ 2 - 3
cf_jb = cf_n / 6 * (cf_skew ^ 2 + cf_kurt ^ 2 / 4)
cf_jbp = exp(-cf_jb / 2)
cf_rs = cf_res[argsort(x)]
cf_lag1 = sum(cf_rs[0:cf_n - 2] .* cf_rs[1:cf_n - 1]) / sum(cf_rs .^ 2)
cf_stat = [cf_n, cf_k, cf_dof, cf_ssr, cf_r2, cf_r2adj, cf_rmse, cf_sigma, cf_chi2, cf_aic, cf_aicc, cf_bic, mean(cf_res), std(cf_res), cf_skew, cf_kurt, cf_jbp, cf_lag1, cf_fit.converged * 1, cf_fit.iterations]
cf_gx = linspace(cf_x0 - 0 * cf_xr, cf_x1 + 0 * cf_xr, 400)
cf_gy = cf_eval(cf_gx, cf_q)
print("exponential decay / growth: R2 =", cf_r2, " adjusted R2 =", cf_r2adj, " RMSE =", cf_rmse, " AIC =", cf_aic, " BIC =", cf_bic)
print("  a =", cf_q[0], " +/- ", cf_se[0], "  95% CI [", cf_lo[0], ",", cf_hi[0], "]")
print("  b =", cf_q[1], " +/- ", cf_se[1], "  95% CI [", cf_lo[1], ",", cf_hi[1], "]")
print("  c =", cf_q[2], " +/- ", cf_se[2], "  95% CI [", cf_lo[2], ",", cf_hi[2], "]")
if cf_fit.converged == false then
  print("CFWARN cf did not converge")
end if
```

The data were generated from `y = 3 exp(-0.5 x) + 0.4` plus noise of 0.05, and
the 95 % intervals of `a`, `b` and `c` bracket 3, 0.5 and 0.4.

## Solve equations mode

Type an expression and get tools around it; every result is again a script.

- **Roots of f(x) = 0, and f(x) = g(x).** If the expression is certainly a
  polynomial in the unknown (a conservative parser that handles `+ - *`,
  integer powers and parentheses with numeric coefficients; anything it is not
  sure about is not guessed), the script is `roots([...])` and lists real and
  complex roots. Otherwise it scans the interval you set for sign changes and
  refines each with `fzero`. A double root, where `f` only touches zero, has no
  sign change; the stationary points reported alongside it show it.
- **Extrema and inflection points** from where `f'` and `f''` vanish: `polyder`
  and `roots` for a polynomial, central differences and the same scan otherwise,
  classified by the sign of the second derivative.
- **Systems** of up to four equations in named unknowns, one per line
  (`x^2 + y^2 = 4`, `x = y`). A system that is linear is detected and solved
  exactly with `solve`, with the coefficient matrix shown; otherwise `fsolve`
  starts from your guesses (default 1) and reports the residual norm and a
  warning when it did not converge. **Try several starting points** runs a grid
  of starts and lists each distinct solution once.
- A live plot of f(x) over the interval with the solutions, minima, maxima and
  inflection points marked.

The multistart script for the circle and the line `x = y` finds both solutions:

```qu
# System of 2 equations in x, y
# Generated by the Solve tool: edit and re-run freely.
#   x^2 + y^2 = 4
#   x = y
function sv_sys(sv_u)
  x = sv_u[0]
  y = sv_u[1]
  return [x^2 + y^2 - (4), x - (y)]
end function
# multistart: a grid of 5^2 starting points between -5 and 5; keep each distinct solution once
sv_K = 5
sv_R = 5
sv_S = zeros(32, 2)
sv_ns = 0
sv_start = zeros(2)
for sv_i = 0 to sv_K ^ 2 - 1
  sv_t = sv_i
  for sv_j = 0 to 1
    sv_dgt = sv_t - sv_K * floor(sv_t / sv_K)
    sv_start[sv_j] = -sv_R + 2 * sv_R * sv_dgt / (sv_K - 1)
    sv_t = floor(sv_t / sv_K)
  end for
  try
    sv_try = fsolve("sv_sys", sv_start, max_iter=200)
    if sv_try.converged and sv_try.norm < 1e-8 and sv_ns < 32 then
      sv_new = 1
      for sv_k = 0 to sv_ns - 1
        if norm(sv_S[sv_k, :] - sv_try.x) < 1e-6 * max(1, norm(sv_try.x)) then
          sv_new = 0
        end if
      end for
      if sv_new == 1 then
        sv_S[sv_ns, :] = sv_try.x
        sv_ns = sv_ns + 1
      end if
    end if
  catch e
    # this start failed; the others still run
  end try
end for
sv_x0 = [1, 1]
sv_sol = fsolve("sv_sys", sv_x0, max_iter=500)
sv_x = sv_sol.x
sv_norm = sv_sol.norm
sv_conv = sv_sol.converged * 1
print("distinct solutions found:", sv_ns)
for sv_k = 0 to sv_ns - 1
  print(sv_S[sv_k, :])
end for
if sv_ns == 0 then
  print("CFWARN no starting point converged: widen the range or check that the system has a solution")
end if
```

## What may be typed

Custom models, ODE right-hand sides, starting values and equations all go through
one parser. It accepts numbers, names, `+ - * / ^`, parentheses and calls to
`sin cos tan asin acos atan atan2 sinh cosh tanh exp log log10 log2 sqrt cbrt
abs sign floor ceil round erf min max`. Anything else (statements, `;`, line
breaks, strings, brackets, `=` inside a model, an unknown function, a Qu
reserved word) is refused with a message before anything runs. An accepted
expression is not pasted into the script: it is parsed and the script receives
text rebuilt from the parse, so a typed expression cannot add code to the
generated script.
