# Qu Studio: the Machine Learning lab

The **ML** tab of Qu Studio takes a table of data to a trained, evaluated
model, and everything it does is an ordinary Qu script. You set things up
with forms; the panel writes the script (shown on the right, with *Copy*,
*Open in editor* and an *edit the code* mode that detaches it from the
forms), runs it in its own interpreter, and draws the lines it prints. There
is no second computation path: the numbers and pictures on screen are what
the script prints, so a result is always reproducible by pressing Run in the
Code tab.

The older example scripts (linear regression, k-means, a small network...)
are still there, under the **Examples** menu at the top of the panel: each
opens as a new editor tab.

## What it does

1. **Data.** Four sources: a built-in synthetic example (generated by Qu
   code, seeded, so it is the same table every time), a CSV file, a numeric
   matrix or vector from the Code tab's session, or text pasted into a box.
   The panel finds the header, the separator and a decimal comma, types each
   column (numeric, category or ignore: change it in the preview table),
   counts missing cells and reports parse problems in plain words. Tables of
   more than 200 pasted rows are written to a temp file the script reads with
   `read_csv`; smaller ones are inline in the script.
2. **Columns.** Pick the target (what to predict) and the features. The
   target defaults to the last column, the features to the rest. Category
   columns are one-hot encoded (first level dropped) or label-coded; missing
   values are dropped, mean-imputed or median-imputed; features are scaled
   with `fit_scaler` (standardise or min-max) fitted on the training rows only
   and applied unchanged to the rest. The class balance or target histogram is
   shown.
3. **Task and model.** Classification, regression, clustering, dimensionality
   reduction (PCA with the variance-explained curve, and t-SNE) and anomaly
   detection (isolation forest). Each model has a hyperparameter form with
   defaults and a one-line description. The tunable ones have a **Tune**
   option that runs `grid_search` over ranges you set, scored by
   cross-validation on the training rows, and refits the best combination.
4. **Evaluation.** A train/test split (a ratio slider and a seed) or k-fold
   cross-validation. Classification gives accuracy, precision, recall, F1,
   ROC-AUC, a coloured confusion matrix, the ROC and precision-recall curves
   and permutation feature importance; regression gives R-squared, RMSE, MAE,
   predicted against actual and a residual plot; clustering gives inertia,
   silhouette, centres, a scatter coloured by cluster (the first two principal
   components when there are more than two features) and an elbow and
   silhouette sweep over k. An optional learning curve plots score against
   training-set size.
5. **Compare models.** Tick several models and the script runs them through
   the same cross-validation folds (`cross_val`, one seed) and ranks them by
   mean and standard deviation: the "which model should I use" view.
6. **Neural network.** A layer builder for tabular data: dense layers with
   relu or linear activation, optional dropout, an optimiser, a learning rate,
   epochs, a validation split and early stopping. The loss and metric curves
   draw as the run goes. The engine trains full-batch with relu or linear
   layers only, so that is exactly what the builder offers: there are no
   mini-batches and no convolutional layers for tabular data. `fit()` runs in
   chunks of *report every N epochs* and the optimiser restarts each chunk.
7. **Save and predict.** *Save the model* adds a `save(...)` of the fitted
   model and its preprocessing to the end of the script (every model here
   round-trips through `save` and `load`; the HDF5 `save_model` needs a build
   feature that is off by default). *Predict on new data* then generates a
   second script that loads the model, applies the same feature encoding and
   scaling to a new CSV and writes the predictions to a CSV.

## A walk-through

Open the ML tab. The default example, *Two Gaussian blobs*, is already
loaded; press **Run**. A random forest is trained on 75% of the rows and the
rest is held out: accuracy, a confusion matrix, ROC and PR curves and the
feature importances appear in a second or two. Switch the example to *XOR*, run
again, and then pick *Logistic regression*: accuracy falls to about 50%,
because no straight line separates the quadrants. Switch to *Compare models*,
tick logistic regression, k-nearest neighbours, a tree, a forest and an SVM,
and Run: the linear model is ranked last.

## The generated script of a regression run

This is what the panel writes for the *Noisy linear (regression)* example
with *Linear regression (OLS)* (the target is `y = 3 x1 - 2 x2 + 1 + noise`
with noise standard deviation 0.5, so the best possible R-squared is
13 / 13.25 = 0.981). The panel puts a block of small `ml_` helper functions
first (they print the `@ml` lines the panel parses and handle missing values
and encoding); below is the part that is specific to the run. It was run with
the real engine (the full script, helpers included, and trimmed here of the lines that only feed the pictures) and prints `r2 0.983`, `rmse 0.474`, `mae 0.389`, and an
importance of about 1.47, 0.57 and 0.00 for `x1`, `x2` and `x3`: the
irrelevant column gets none.

```qu,ignore
# ---- Data: built-in example "Noisy linear (regression)" (generated here, seeded)
ml_x = randn(300, 3, seed = 51)
ml_y = 3 * ml_x[:, 0] - 2 * ml_x[:, 1] + 1 + 0.5 * randn(300, seed = 52)
ml_t = table(x1 = ml_x[:, 0], x2 = ml_x[:, 1], x3 = ml_x[:, 2], y = ml_y)

# ---- Features: 3 numeric
ml_f0 = ml_num(ml_t.x1)
ml_f1 = ml_num(ml_t.x2)
ml_f2 = ml_num(ml_t.x3)
X = vstack(ml_f0, ml_f1, ml_f2)'
y = ml_num(ml_t.y)   # target: y

# ---- Missing values: rows with any missing value are dropped
ml_n0 = rows(X)
ml_ok = ml_ok_rows(X, y, true)
X = X[ml_ok, :]
y = y[ml_ok]

# ---- Preprocessing, fitted on the rows a model is trained on and applied unchanged to the rest
function ml_prep_fit(Xtr)
    fill = ml_fill_values(Xtr, "mean")
    sc = fit_scaler(ml_fillna(Xtr, fill), method = "standard")
    return {fill = fill, scaler = sc}
end function

function ml_prep_apply(P, X)
    return P.scaler.transform(ml_fillna(X, P.fill))
end function

# ---- Hold-out split: 25% of the rows are never seen while fitting
ml_sp = train_test_split(X, y, test_size = 0.25, seed = 1)
Xtr = ml_sp.X_train
ytr = ml_sp.y_train
Xte = ml_sp.X_test
yte = ml_sp.y_test
ml_P = ml_prep_fit(Xtr)
Xtr = ml_prep_apply(ml_P, Xtr)
Xte = ml_prep_apply(ml_P, Xte)

# ---- Model: Linear regression (OLS)
function ml_fit(X, y)
    return ols_model(X, y)
end function
ml_model = ml_fit(Xtr, ytr)

# ---- Evaluation on the held-out rows
ml_pred = ml_model.predict(Xte)
ml_metric("r2", r2(yte, ml_pred))
ml_metric("rmse", rmse(yte, ml_pred))
ml_metric("mae", mae(yte, ml_pred))

# ---- Feature importance: how much the test score drops when one column is shuffled
ml_imp = permutation_importance(ml_model, Xte, yte, n_repeats = 5)
ml_emit("importance", ml_imp)
```

Change `ols_model` to `ridge_model(X, y, 1)`, or to a forest, and Run again:
the script is yours.

## Engine facts worth knowing

- `accuracy` as a builtin, and `cross_val(..., metric = "accuracy")`, treat
  any prediction other than exactly 0 or 1 as a score to threshold at 0.5, so
  both are wrong for classes numbered 2 and up. The lab computes accuracy
  itself (`sum(y == p) / length(y)`) and, for the model comparison with more
  than two classes, ranks by macro F1 and says so.
- `logistic_model` and `svm_model` take exactly two classes; the panel
  refuses them for a target with more, before running.
- A table's text column reads into a list of strings, and a blank cell in a
  numeric column turns the whole column into text; the script's `ml_num`
  turns such columns back into numbers with `NaN` for blanks.
- `permutation_importance` needs a model with a `score`; for naive Bayes, LDA,
  QDA and PLS the script falls back to a small shuffle-and-rescore helper.
- ROC and PR curves need scores. Logistic regression, LDA, naive Bayes and
  the network have them (computed from the fitted model's fields); the other
  models return labels only, and the panel says that the curve then has a
  single operating point.
