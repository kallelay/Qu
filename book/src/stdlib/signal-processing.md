# Signal Processing & Filters

This chapter is a reference table generated by reading the interpreter's own builtin dispatch table (`engine/crates/qu-interp/src/lib.rs`, the `call_builtin` match statement) rather than hand-written prose, so it reflects exactly what runs today.

## Example data

Every worked example below is self-contained and generates whatever data it needs — a sine, a chirp, a burst of noise — right there in its own code block, so nothing needs a data file. The snippet here shows the shape that data typically takes: a two-tone signal plus noise, and a matching lowpass filter, built with functions documented in [Signal Generation](#signal-generation) and [Filter Design](#filter-design). It reappears, inlined, as the starting point of the [Butterworth design example](#butterworth-design-batch-and-streaming-filtering) further down.

```qu
fs     = 1000
t      = (0 to 999) / fs
signal = sin(2 * pi * 50 * t) + 0.5 * sin(2 * pi * 220 * t) + 0.1 * randn(1000, seed = 2)
lp     = butter(4, "low", 100, fs)          # 4th-order low-pass at 100 Hz
print("signal length: {length(signal)}, lp sections: {shape(lp.sos)[0]}")
```

## Transforms

| Function | Signature | Description |
|---|---|---|
| `fft` / `fftc` | `fft(x, [n])` | Forward DFT (Bluestein/rustfft-accelerated). `x` is a length-N real or complex vector; `n` (optional number) zero-pads/truncates `x` to `n` samples before transforming, defaulting to `N`. Returns a length-`n` complex vector (`CVec`). `fftc` is an explicit-complex alias of the same function, identical signature and return. |
| `ifft` | `ifft(X, [n])` | Inverse DFT, same underlying kernel as `fft` run in reverse. `X` is a length-N complex vector (`CVec`); `n` (optional number, default `N`) is the target length, same zero-pad/truncate rule as `fft`. Returns a length-`n` `CVec`. |
| `rfft` | `rfft(x)` | Real-optimized half-spectrum FFT. `x` is a length-N real vector. Returns a length-`floor(N/2)+1` `CVec` (DC through Nyquist) — a real signal's spectrum is Hermitian-symmetric, so only the non-negative-frequency half is returned. |
| `irfft` | `irfft(half_spectrum, n)` | Inverse of `rfft`. `half_spectrum` is a length-`floor(n/2)+1` complex vector (`CVec`); `n` (required number), the real output length, can't be recovered from the half-spectrum's length alone (even and odd `n` can share a half-length). Returns a length-`n` real vector. (`fftr` is a deprecated second name for this — see below.) |
| `dft` | `dft(x)` | `x` is a length-N real or complex vector. Returns a length-N `CVec`. The direct, textbook O(n²) transform, kept as an independent reference implementation to validate `fft` against and as the definitional basis `goertzel` specializes. |
| `idft` | `idft(X)` | `X` is a length-N complex vector (`CVec`). Returns a length-N `CVec`. Inverse of `dft`, same O(n²) direct implementation. |
| `goertzel` | `goertzel(x, k)` | `x` is a length-N real vector; `k` (number) is the bin index to evaluate — need not be an integer (evaluates the DFT at an arbitrary point between the FFT's grid bins, a "K-point DFT"). Returns a single complex scalar, the DFT value at bin `k` in O(n) — the standard tool for checking a handful of specific frequencies without paying for a whole FFT. |
| `goertzel_freq` | `goertzel_freq(x, fs, freq)` | `x` is a length-N real vector; `fs` (number, Hz) is the sample rate; `freq` (number, Hz) is the frequency to evaluate. Returns a single complex scalar. `goertzel` parameterized by a real frequency rather than a raw bin index — the common case of checking a known tone frequency at a fixed sample rate. |
| `vanicek` | `vanicek(t, x, freqs)` | `t` is a length-N vector of sample times (need not be uniformly spaced); `x` is the matching length-N vector of samples; `freqs` is a length-M vector of frequencies (Hz) to evaluate. Returns a length-M real vector, the power spectrum at each requested frequency — Vanicek's Least-Squares Spectral Analysis, valid for unevenly-sampled `(t, x)` where `fft`/`dft`/`goertzel` (which all assume uniform sampling) don't apply. |
| `dct` | `dct(x)` | `x` is a length-N real vector. Returns a length-N real vector. Orthonormal DCT-II (MATLAB `dct` / `scipy.fft.dct(norm='ortho')` convention). |
| `idct` | `idct(X)` | `X` is a length-N real vector of DCT coefficients. Returns a length-N real vector. Orthonormal DCT-III, the exact inverse of `dct` (round-trips exactly since the basis is orthonormal). |
| `dwt` | `dwt(x)` | `x` is a length-N real vector (N should be even). Returns a `(2, N/2)` matrix — row 0 is the approximation band, row 1 is the detail band (Qu has no multi-return). One level of the orthogonal Haar discrete wavelet transform; only the Haar family is implemented. |
| `idwt` | `idwt(m)` | `m` is a `(2, N)` matrix of `[approx; detail]` rows (each row length N). Returns a length-`2N` real vector, reconstructing the original signal. Inverse of `dwt`. |
| `stft` | `stft(x, nfft, [hop=nfft/2])` | `x` is a length-N real vector; `nfft` (number) is the frame/FFT size; `hop` (optional number, default `nfft/2`, i.e. 50% overlap) is the sample stride between successive frame starts. Returns an `nfft`×`num_frames` complex matrix (`CMat`, the full per-frame spectrum, not one-sided) — one column per frame, built from a periodic-Hann-windowed FFT per frame. `abs(stft(x, ...))` is a spectrogram. |
| `hilbert` | `hilbert(x)` | `x` is a length-N real vector. Returns a length-N complex vector (`CVec`), the analytic signal `x + j*H[x]`. `abs(hilbert(x))` is `x`'s envelope; `imag(hilbert(x))` is the Hilbert transform of `x` itself. |

## Convolution, Correlation & Peaks

| Function | Signature | Description |
|---|---|---|
| `conv` | `conv(x, h, [mode="full"])` | `x` is a length-N vector, `h` a length-M vector (the kernel/impulse response). `mode` (optional string) follows MATLAB's `conv`/NumPy's `convolve` naming: `"full"` (default, length `N+M-1`, every nonzero-overlap sample), `"same"` (length N, the middle samples aligned with the input), `"valid"` (length `max(N,M)-min(N,M)+1`, only where `h` fully overlaps `x`). Returns a vector of the length implied by `mode`. |
| `xcorr` | `xcorr(x, [y])` | `x` is a length-N vector; `y` (optional length-M vector, defaults to `x` for autocorrelation). Returns a length-`N+M-1` vector, the full lag range (zero lag at the middle for equal-length inputs). |
| `find_peaks` | `find_peaks(x, [height=], [distance=], [prominence=], [width=], [rel_height=0.5])` | `x` is a length-N vector. `height` (optional number): minimum peak value; `distance` (optional number, samples): minimum separation, enforced greedily by height so a close cluster keeps its tallest member; `prominence` (optional number): minimum rise above surrounding terrain (the real bounding-minima computation, not just local-maxima detection); `width` (optional number, samples): minimum width at `rel_height` (default `0.5`, i.e. half-prominence) of the peak's prominence below its height, via linear interpolation of the crossing — matches `scipy.signal.find_peaks`'s own algorithm. Kwarg names match SciPy; the original `min_height`/`min_distance`/`min_prominence` names are still accepted as aliases. Returns a vector of 0-indexed integer indices into `x`, one per surviving local maximum. |
| `findpeaks` | `findpeaks(x, [min_peak_height=], [min_peak_distance=])` | `x` is a length-N vector; `min_peak_height`/`min_peak_distance` (optional numbers) as above. MATLAB-style `[peaks, locations] = findpeaks(x, ...)`. Qu has no multi-return/tuple-unpacking assignment, so this returns a `Model` (kind `"findpeaks"`) with fields `peaks` (a vector of the peak values), `locations` (a vector of their 0-indexed integer indices into `x` — not MATLAB's 1-indexing), `prominences` (a vector, one per peak, the real prominence value) and `widths` (a vector, one per peak, the width in samples at `rel_height=0.5`) — the same named-field convention `qr`/`lu`/`svd`/`eig` use. Shares its peak-finding/non-max-suppression logic with `find_peaks` above. |

#### Overloads: `conv`

| Call | Output length | What it keeps |
|---|---|---|
| `conv(x, h)` / `conv(x, h, mode="full")` | `N+M-1` | Every nonzero-overlap sample — the default. |
| `conv(x, h, mode="same")` | `N` | The middle samples, aligned with `x`. |
| `conv(x, h, mode="valid")` | `max(N,M)-min(N,M)+1` | Only the samples where `h` fully overlaps `x`. |

`mode` is a keyword argument, not a third positional one. The example below convolves the same 4-sample `x` and 3-sample `h` all three ways and prints each result's length alongside its values.

```qu
x = [1, 2, 3, 4]
h = [1, 1, 1]
f = conv(x, h)
s = conv(x, h, mode="same")
v = conv(x, h, mode="valid")
print("full ({length(f)}): {f}")     # full (6): [1, 3, 6, 9, 7, 4]
print("same ({length(s)}): {s}")     # same (4): [3, 6, 9, 7]
print("valid ({length(v)}): {v}")    # valid (2): [6, 9]
```

## Level & Power Conversions

| Function | Signature | Description |
|---|---|---|
| `mag2db` | `mag2db(x)` | `x`: a number or vector (amplitude/voltage ratio). Returns the same shape: `20*log10(x)`. AMPLITUDE/field-quantity convention. |
| `db` | `db(x)` | Alias of `mag2db(x)` above (`20*log10(x)`, amplitude convention) — the bare SciPy/general-DSP-flavored spelling. |
| `db2mag` | `db2mag(db)` | `db`: a number or vector (decibel value). Returns the same shape: `10^(db/20)` — inverse of `mag2db`. |
| `pow2db` | `pow2db(x)` | `x`: a number or vector (power ratio). Returns the same shape: `10*log10(x)`. POWER-domain convention. |
| `db_power` | `db_power(x)` | Alias of `pow2db(x)` above (`10*log10(x)`, power convention) — the bare SciPy/general-DSP-flavored spelling. |
| `db2pow` | `db2pow(db)` | `db`: a number or vector (decibel value). Returns the same shape: `10^(db/10)` — inverse of `pow2db`/`db_power`. |

`mag2db`/`db2mag`/`pow2db`/`db2pow` are the canonical, MATLAB-derived names; `db`/`db_power` are aliases for callers coming from plain-SciPy/DSP habit who reach for a bare `db()` first. Whether a ratio is a power or an amplitude changes the factor of 10 vs. 20 — `db`/`mag2db` are for field quantities (V, A, Pa, ...), `db_power`/`pow2db` are for quantities already a power/energy ratio (W, W/Hz, `|X|^2`, ...). Getting this backwards is the classic dB mixup.

## Spectral Analysis

| Function | Signature | Description |
|---|---|---|
| `spectrogram` | `spectrogram(x, [nfft=256], [hop=nfft/2], [fs=1])` | `x`: a length-N real vector or `Signal`. `nfft`/`hop` (optional numbers): STFT frame size and hop, as in `stft`. `fs` (optional number, Hz): scales row ticks to Hz and column ticks to seconds. **If `x` is a `Signal`, its own `Fs` is used and `fs` need not be passed**; passing one that disagrees with the signal's rate is an error rather than a silent relabelling (see *Which rate is used*, below). The default of `1` applies only to a plain vector, which carries no rate. Renders a heatmap of `stft(x, nfft, hop)`'s magnitude, restricted to the positive-frequency half (`nfft/2+1` rows), in dB (floored at -120dB); frequency increases upward (row 0 = Nyquist). Draws **and** returns: the surface would otherwise be unreachable, with no way to read a level off it or hand it to Qu Studio's Interactive Mode. Returns a `Record` with fields `db` (an `(nfft/2+1, frames)` `Mat` of dB magnitudes, row 0 = DC — the honest axis order, the opposite of the drawn picture's), `freq` (a length-`nfft/2+1` `Vec`, Hz) and `time` (a length-`frames` `Vec`, seconds). |
| `spectral_entropy` | `spectral_entropy(x, [nfft=256], [hop=nfft/2])` | `x`: a length-N real vector. `nfft`/`hop` (optional numbers): STFT frame size/hop as in `stft`. Returns a vector of length `num_frames` (one value per STFT frame), each the Shannon entropy of that frame's normalized power spectrum, scaled to `[0, 1]`: low when energy concentrates in a few bins (a clean tone), high when spread across many (broadband noise). |
| `welch` | `welch(x, fs, [nperseg=min(256,len(x))], [noverlap=nperseg/2], [window="hann"])` | `x`: a length-N real vector; `fs` (number, Hz): sample rate. `nperseg` (optional number): samples per segment; `noverlap` (optional number): overlap between segments; `window` (optional string, e.g. `"hann"`/`"hamming"`/`"blackman"`): window applied to each segment. Returns a length-`nperseg/2 + 1` real vector, the one-sided PSD (DC to Nyquist) in SciPy's `"density"` scaling — Welch's method segments `x` into overlapping windowed frames and averages their squared-magnitude spectra. Pair with `linspace(0, fs/2, length(psd))` for the frequency axis. |
| `periodogram` | `periodogram(x, fs, [window="hann"])` | `x`: a length-N real vector; `fs` (number, Hz); `window` (optional string). Returns a length-`N/2 + 1` real vector, same scaling as `welch`. The simplest PSD estimate — `welch`'s one-segment (`nperseg=length(x)`, `noverlap=0`), no-averaging special case. |
| `csd` | `csd(x, y, fs, [nperseg=min(256,len(x),len(y))], [noverlap=nperseg/2], [window="hann"])` | `x`/`y`: equal-length real vectors; `fs` (number, Hz). Returns a length-`nperseg/2 + 1` complex vector (`CVec`), the one-sided cross-spectral density `Pxy` — Welch's method, sharing `welch`'s own framing/windowing/averaging exactly, so it lines up bin-for-bin with `welch(x, ...)`/`welch(y, ...)`. `abs(csd(x, y, fs))` is cross-power magnitude, `angle(csd(x, y, fs))` is phase. |
| `spectral_coherence` | `spectral_coherence(x, y, fs, [nperseg=], [noverlap=], [window="hann"])` | `x`/`y`: equal-length real vectors; `fs` (number, Hz). Returns a length-`nperseg/2 + 1` real vector, the magnitude-squared coherence `\|Pxy\|^2 / (Pxx*Pyy)` in `[0, 1]` — `1` at a frequency where `y` is an exact linear/time-invariant function of `x`'s content there. Unrelated to `coherence(A)` (see the Compressed Sensing chapter) — the largest inner product between two different normalised columns of a compressed-sensing matrix — which is a different, pre-existing function under its own name. |
| `nyquist` | `nyquist(Z, [color=], [label=], [marker="o"])` | `Z`: a length-N complex vector (`CVec`, the impedance spectrum). `color`/`label`/`marker` (optional strings): plot styling. The standard EIS plot: `Re(Z)` on x, `-Im(Z)` on y (the impedance-spectroscopy sign convention every EIS instrument uses, so capacitive/inductive behavior plots in the upper half-plane). Returns `Nothing` — this call is made for the figure it draws. |
| `bode_magnitude` | `bode_magnitude(Z, freqs, [color=], [label=], [marker="line"])` | `Z`: a length-N complex vector (`CVec`); `freqs`: the matching length-N real vector (Hz). `color`/`label`/`marker` (optional strings). Magnitude half of a Bode plot: `20*log10(\|Z\|)` vs. log-scaled frequency. Returns `Nothing` — this call is made for the figure it draws. |
| `bode_phase` | `bode_phase(Z, freqs, [color=], [label=], [marker="line"])` | `Z`: a length-N complex vector (`CVec`); `freqs`: the matching length-N real vector (Hz). `color`/`label`/`marker` (optional strings). Phase half of a Bode plot: `arg(Z)` in degrees vs. log-scaled frequency. Kept as a separate call from `bode_magnitude` (rather than one builtin silently building a 2-panel figure) so a script stays in control of its own subplot layout. Returns `Nothing` — this call is made for the figure it draws. |

## Adaptive Decomposition

| Function | Signature | Description |
|---|---|---|
| `emd` | `emd(x, [max_imfs=])` | `x`: a length-N real vector. `max_imfs` (optional number): caps the number of IMFs extracted. Empirical Mode Decomposition: splits `x` into oscillatory intrinsic mode functions (IMFs, highest frequency first) plus a residual trend, via the standard sifting algorithm. Returns a `Model` (kind `"emd"`) with fields `imfs` (a `K`×N matrix, one IMF per row), `residual` (a length-N vector), `count` (a number, `K`). `sum(e.imfs, axis=0) + e.residual` reconstructs `x` exactly. |
| `vmd` | `vmd(x, k, [alpha=2000])` | `x`: a length-N real vector; `k` (number, integer): the exact number of modes to extract; `alpha` (optional number): bandwidth-penalty strength. Variational Mode Decomposition: decomposes `x` into exactly `k` band-limited modes by minimizing each mode's bandwidth around its own center frequency, solved by ADMM (not sifting, unlike `emd`). Returns a `Model` (kind `"vmd"`) with fields `modes` (a `k`×N matrix, one mode per row) and `center_freqs` (a length-`k` vector, normalized to cycles/sample — `0.5` is Nyquist). |

## Signal Features

| Function | Signature | Description |
|---|---|---|
| `energy` | `energy(x)` | `x`: a length-N vector or `Signal`. Returns a single number, `sum(x.^2)` — total signal energy. See `tkeo` for a per-sample instantaneous estimate instead. |
| `tkeo` | `tkeo(x)` | `x`: a length-N real vector. Returns a length-`(N-2)` vector (like `diff`, doesn't pad — the definition needs a neighbor on each side). Teager-Kaiser Energy Operator, a cheap near-instantaneous nonlinear energy tracker: `psi[x(n)] = x(n)^2 - x(n-1)*x(n+1)`. |
| `ste` | `ste(x, [win=256], [hop=win/2])` | `x`: a length-N real vector. `win` (optional number): frame length in samples; `hop` (optional number, default `win/2`): samples between successive frame starts. Returns a vector of length `num_frames`, one energy value per frame. Short-time energy: the windowed extension of `energy(x)` over sliding, overlapping frames — the standard way to track how a signal's power evolves over time (e.g. locating bursts in EMG, or voiced/silent segments in speech). |

## Filter Design

Every filter-design function returns a `Model` of kind `"filter"` (field `sos` for IIR designs — a `num_sections`×5 matrix, one biquad section per row as `[b0,b1,b2,a1,a2]` — or field `b` for FIR designs, a plain length-`n+1` tap vector). `order`/`n` is a number (the filter order, an integer); `kind` (string) for the IIR designs accepts `"low"`/`"high"`/`"band"`/`"stop"`, with `"lowpass"`/`"highpass"`/`"bandpass"`/`"bandstop"`/`"notch"` as more readable aliases; `cutoff` is one Hz number for low/high or a length-2 vector `[low, high]` for band/stop; `fs` is a number, the sample rate in Hz.

| Function | Signature | Description |
|---|---|---|
| `butter` | `butter(order, kind, cutoff, fs)` | `order`: number (filter order); `kind`: string; `cutoff`: number or length-2 vector (Hz); `fs`: number (Hz). Returns a `Model` (kind `"filter"`, field `sos`). Digital Butterworth filter as a cascade of second-order sections — monotonic, ripple-free response. |
| `ellip` | `ellip(order, ripple_db, atten_db, kind, cutoff, fs)` | `order`: number; `ripple_db`/`atten_db`: numbers (dB); `kind`: string; `cutoff`: number or length-2 vector (Hz); `fs`: number (Hz). Returns a `Model` (kind `"filter"`, field `sos`). Digital elliptic (Cauer) filter, equiripple in both the passband (within `ripple_db` dB) and stopband (at least `atten_db` dB down) — the steepest transition band of the classical IIR families at a given order, at the cost of ripple in both bands. `cutoff` is where gain first drops below `-ripple_db` (MATLAB/SciPy convention), not the -3dB point. |
| `cheby1` | `cheby1(order, ripple_db, kind, cutoff, fs)` | `order`: number; `ripple_db`: number (dB); `kind`: string; `cutoff`: number or length-2 vector (Hz); `fs`: number (Hz). Returns a `Model` (kind `"filter"`, field `sos`). Digital Chebyshev Type I filter: equiripple passband (bounded by `ripple_db` dB), monotonic stopband, steeper rolloff than Butterworth at the same order. |
| `cheby2` | `cheby2(order, atten_db, kind, cutoff, fs)` | `order`: number; `atten_db`: number (dB); `kind`: string; `cutoff`: number or length-2 vector (Hz); `fs`: number (Hz). Returns a `Model` (kind `"filter"`, field `sos`). Digital Chebyshev Type II (inverse Chebyshev) filter: monotonic passband, equiripple stopband (at least `atten_db` dB down starting at the stopband edge), flatter passband than Type I at the cost of a wider transition band. |
| `fir1` | `fir1(n, cutoff, [kind="low"], [window="hamming"], [fs=2], [beta=])` | `n`: number (order, taps = `n+1`); `cutoff`: number or length-2 vector; `kind` (optional string); `window` (optional string: `"hamming"`, `"hann"`/`"hanning"`, `"blackman"`, or `"kaiser"` — the last needs `beta=`, a required number when chosen); `fs` (optional number, default `2.0`, MATLAB's normalized convention where `1` = Nyquist) — pass an explicit `fs=` for `butter`-style Hz cutoffs. Returns a `Model` (kind `"filter"`, field `b`, a length-`n+1` vector). Windowed-sinc FIR design (MATLAB/SciPy `fir1`): the ideal impulse response truncated to `n+1` taps and multiplied by the requested window, normalized to unity gain at the passband center. |
| `firls` | `firls(n, freq_bands, desired, [weights=])` | `n`: number, must be even (taps = `n+1`); `freq_bands`: a length-`2B` vector of band-edge pairs (normalized `0..1`, `1`=Nyquist); `desired`: a length-`2B` vector, the target amplitude at each edge; `weights` (optional length-`B` vector, default all `1.0`), one weight per band. Returns a `Model` (kind `"filter"`, field `b`, a length-`n+1` vector). Least-squares FIR design (MATLAB/SciPy `firls`): given a piecewise-linear desired response, finds the symmetric FIR minimizing weighted squared error. |

#### Overloads: `butter`

| Call | `cutoff` shape |
|---|---|
| `butter(order, "low"/"high", cutoff, fs)` | A single Hz number — the low-pass or high-pass edge. |
| `butter(order, "band"/"stop", cutoff, fs)` | A length-2 `[low, high]` Hz vector — the passband/stopband edges (`"stop"`/`"notch"` cuts that band out instead of keeping it). |

`kind` doesn't just relabel the same response — it changes what `cutoff` itself has to be. The example below designs a lowpass (scalar cutoff) and a bandpass (2-element cutoff) at the same order and sample rate, confirming each yields its own `sos` section count.

```qu
fs = 1000
lp = butter(4, "low", 100, fs)
bp = butter(4, "band", [80, 120], fs)
print("lowpass sections: {shape(lp.sos)[0]}")    # lowpass sections: 2
print("bandpass sections: {shape(bp.sos)[0]}")   # bandpass sections: 4
```

| `fir1(n, cutoff, kind="band"/"stop", ...)` | A length-2 `[low, high]` number/Hz vector. |

Same `kind`-driven `cutoff` shape as the IIR family above, even though the tap count (`n+1`) stays fixed regardless of which branch runs — only the ideal response being windowed changes.

```qu
fs = 1000
lp = fir1(20, 100, kind="low", fs=fs)
bp = fir1(20, [80, 120], kind="band", fs=fs)
print("lowpass taps: {length(lp.b)}")    # lowpass taps: 21
print("bandpass taps: {length(bp.b)}")   # bandpass taps: 21
```

## Streaming & Batch Filter Application

| Function | Signature | Description |
|---|---|---|
| `sosfilt` | `sosfilt(filt, x)` | `filt`: a `Model` (kind `"filter"`, field `sos` or `b`); `x`: a length-N vector or `Signal`. Returns a same-length vector or `Signal` (keeping `x`'s own `Fs` on the way out, when `x` is a `Signal`). Causal (one-pass) filtering, with the usual IIR phase lag. Branches on the filter's representation: `sos` uses the biquad cascade, `b` (FIR) is `conv(x, b, "full")` truncated to `len(x)`. |
| `filter_ba`, `lfilter` | `filter_ba(b, a, x)` | `b`, `a`: vectors (numerator/denominator coefficients); `x`: a length-N vector or `Signal`. Returns a same-length vector or `Signal`. Apply a transfer function given as raw numerator and denominator coefficients, direct form II transposed. For a function you derived yourself, or a script ported from MATLAB (`filter(b, a, x)`) or scipy (`lfilter`) — `filter` itself is the higher-order predicate filter here, so the name is taken. Warns above order 8, where a direct form loses accuracy and second-order sections do not. |
| `filtfilt` | `filtfilt(filt, x)` | `filt`: a `Model` (kind `"filter"`); `x`: a length-N vector or `Signal`. Returns a same-length vector or `Signal`, same `Fs`-preserving convention as `sosfilt`. | `filter_init` | `filter_init(filt)` | `filt`: a `Model` (kind `"filter"`). Returns a `Model` (kind `"filter_state"`) holding fresh all-zero streaming state for sample-at-a-time filtering: field is an `(n_sections, 2)` biquad-state matrix for an IIR (`sos`) filter, or a length-`(len(b)-1)` all-zero delay vector for an FIR (`b`) filter. |
| `filter_next` | `filter_next(state, x)` | `state`: a `Model` (kind `"filter_state"`, from `filter_init` or a prior `filter_next`); `x`: a single number (one new sample). Returns a new `"filter_state"` `Model` (field `y`, a number, holds the filtered output). Use as `state = filter_next(state, next_sample)` in a loop, reading `state.y` each time — the real-time/serial-fed-data counterpart to `sosfilt`/`filtfilt`. |

#### Overloads: `sosfilt`

#### Case: IIR filter (`sos`)

`filt` a `Model` with a `sos` field (`butter`/`ellip`/`cheby1`/`cheby2`). Runs `x` through the biquad cascade section by section.

```qu
fs = 100
t = (0 to 19) / fs
x = sin(2*pi*10*t)
iir = butter(2, "low", 20, fs)
y_iir = sosfilt(iir, x)
print("IIR-filtered length: {length(y_iir)}")   # IIR-filtered length: 20
```

#### Case: FIR filter (`b`)

`filt` a `Model` with a `b` field (`fir1`/`firls`). Runs `x` through `conv(x, b, "full")`, truncated back to `length(x)` — no biquad state at all.

```qu
fs = 100
t = (0 to 19) / fs
x = sin(2*pi*10*t)
fir = fir1(6, 20, kind="low", fs=fs)
y_fir = sosfilt(fir, x)
print("FIR-filtered length: {length(y_fir)}")   # FIR-filtered length: 20
```

#### Overloads: `filter_init`

#### Case: IIR filter (`sos`)

`filt` a `Model` with a `sos` field. Returns a `filter_state` `Model` whose `z` is an `(n_sections, 2)` all-zero biquad-state matrix — 2 numbers of memory per section.

```qu
fs = 1000
iir = butter(2, "low", 100, fs)
si = filter_init(iir)
print("IIR state shape: {shape(si.z)}")   # IIR state shape: [1, 2]
```

#### Case: FIR filter (`b`)

`filt` a `Model` with a `b` field. Returns a `filter_state` `Model` whose `z` is a plain length-`(len(b)-1)` all-zero delay vector — just the last few inputs, no feedback to track.

```qu
fs = 1000
fir = fir1(6, 100, kind="low", fs=fs)
sf = filter_init(fir)
print("FIR state length: {length(sf.z)}")   # FIR state length: 6
```

#### Overloads: `poles`

#### Case: IIR filter (`sos`)

`filt` a `Model` built by `butter`/`ellip`/`cheby1`/`cheby2` (or anything else with a `sos` field). Returns each biquad section's `z^2 + a1*z + a2 = 0` roots as a `CVec` — genuine, generally complex, poles.

```qu
fs = 1000
iir = butter(2, "low", 100, fs)
print("IIR poles: {poles(iir)}")
# IIR poles: [0.57149 + 0.293599i, 0.57149 - 0.293599i]
```

#### Case: FIR filter (`b`)

`filt` a `Model` built by `fir1`/`firls` (a `b` field, no `sos`). An FIR filter has no feedback at all, so every pole sits at the origin regardless of the design — the same fact `is_stable`'s "an FIR filter is always stable" relies on.

```qu
fs = 1000
fir = fir1(6, 100, kind="low", fs=fs)
print("FIR poles: {poles(fir)}")
# FIR poles: [0, 0, 0, 0, 0, 0]
```

#### Overloads: `zeros`

| Call | Returns |
|---|---|
| `zeros(n)` | A length-`n` real vector of `0.0`s — the plain array constructor. |
| `zeros(r, c)` | An `(r, c)` real matrix of `0.0`s. |
| `zeros(filt)` | A `CVec` of the filter `Model`'s zeros (IIR: each section's `b0*z^2+b1*z+b2=0` roots; FIR: the tap polynomial's roots) — nothing to do with array construction at all. |

The single argument's own type is what tells these apart: a plain number or pair of numbers builds an array, while a filter `Model` instead reads off `poles(filt)`'s zero-side counterpart. The example below builds a plain vector and a matrix, then asks the same name for a 2nd-order lowpass Butterworth's zeros.

```qu
v = zeros(4)
m = zeros(2, 3)
fs = 1000
lp = butter(2, "low", 100, fs)
zf = zeros(lp)
print("vector: {v}")             # vector: [0, 0, 0, 0]
print("matrix shape: {shape(m)}")  # matrix shape: [2, 3]
print("filter zeros: {zf}")      # filter zeros: [-1, -1]
```

## Signal Generation

> **`square` is a square-WAVE generator, not "x squared."** The name is easy
> to misread as an elementwise math function, e.g. piping data through it by
> mistake: `x = [1,2,3,4,5]; x |> square |> sum`. That's a type error now
> (see below), but if it's ever ambiguous at a call site, spell it
> `signals.square(...)` instead — see "`signals.` sugar" below for the full
> namespace, which exists purely for this disambiguation and is otherwise
> 100% identical to the bare name.
>
> Every generator below validates its numeric arguments strictly: an
> argument that's simply omitted still uses its documented default, but an
> argument that IS supplied with the wrong type (e.g. a `Vec`/`Signal`
> where a plain number was expected) is a clear error naming the function,
> the argument, and what was actually given — never a silent fallback to
> the default.

| Function | Signature | Description |
|---|---|---|
| `sine` | `sine(freq, fs, n, [phase=0], [amplitude=1])` | `freq`, `fs`: numbers (Hz); `n`: number (integer sample count); `phase` (optional number, radians); `amplitude` (optional number). Returns a length-`n` `Signal` (carries `Fs=fs`). Single-tone generator built on the same synthesis kernel as `multisine` (a sine is a one-tone multisine). |
| `multisine` | `multisine(freqs, amps, fs, n, [phases=])` | `freqs`, `amps`: length-K vectors (Hz, amplitude per tone); `fs`: number (Hz); `n`: number (integer sample count); `phases` (optional length-K vector, radians). Returns a length-`n` `Signal`. Sum of cosines at the given frequencies/amplitudes. Defaults to Schroeder's phase formula (`phi_k = -k(k-1)*pi/K`) when `phases` isn't given — keeps crest factor low without iterative optimization. |
| `chirp` / `sweep` | `chirp(f0, f1, fs, n, [method="linear"])` | `f0`, `f1`, `fs`: numbers (Hz); `n`: number (integer sample count); `method` (optional string: `"linear"` or `"logarithmic"`/`"log"`/`"exponential"`). Returns a length-`n` `Signal`. | `impulse` | `impulse(n, [index=0], [amplitude=1])` | `n`: number (integer length); `index` (optional number, integer sample position); `amplitude` (optional number). | `square` (`signals.square`) | `square(freq, fs, n, [duty=0.5])` | `freq`, `fs`: numbers (Hz); `n`: number (integer sample count); `duty` (optional number in `(0,1)`, fraction of each period spent at `+1`). Returns a length-N `Signal` (same length as `modulator`). Natural-sampling pulse-width modulation: `+1` where `modulator` exceeds the carrier wave oscillating in `[-1,1]` at `carrier_freq`, else `-1`. |
| `sawtooth` (`signals.sawtooth`) | `sawtooth(freq, fs, n)` | `freq`, `fs`: numbers (Hz); `n`: number (integer sample count). Returns a length-`n` `Signal`. | `triangle` (`signals.triangle`) | `triangle(freq, fs, n)` | `freq`, `fs`: numbers (Hz); `n`: number (integer sample count). Returns a length-`n` `Signal`. ### `signals.` sugar

`signals.square(...)`/`signals.impulse(...)`/`signals.pwm(...)`/
`signals.sawtooth(...)`/`signals.triangle(...)` are part of the same small,
closed `table.`/`timer.` "namespace-dot" alias set (§ ergonomic API layer,
2026-08-31; `signals.` added § argument-validation audit, 2026-09-01): the
parser recognizes exactly those five `signals . method (` token sequences
and rewrites each, at parse time, straight to the bare call of the same
name (`signals.square(f, fs, n)` becomes exactly `square(f, fs, n)`) — so
evaluation is byte-identical either way. Unlike `table.load`/`timer.start`,
these aliases don't rename anything; the point is purely disambiguation —
an unambiguous way to spell the call when `square` in particular could
otherwise be misread as "x squared." `signals` is not a namespace value; it
still works as an ordinary variable (`signals = 5; print(signals)`).

The example below builds the same pulse train two ways — once through the bare `square` name, once through `signals.square` — and prints both to confirm the parser really does treat them as the exact same call.

```qu
a = square(100, 1000, 20, duty=0.25)
b = signals.square(100, 1000, 20, duty=0.25)   # identical to `a`
print("square: {a}")
print("signals.square matches: {max(abs(a - b)) < 1e-12}")
```

## Resampling

| Function | Signature | Description |
|---|---|---|
| `resample_to` | `resample_to(signal, new_fs)` | `signal`: a length-N `Signal` (must carry a known `Fs`); `new_fs`: a number (Hz), the target sample rate. Returns a new `Signal` at `Fs=new_fs`, whose length is whatever it takes to span the *same* start/end time as the input (generally not N). Real resampling, not a relabel: evaluates the signal's own piecewise-linear waveform (through its samples at their original instants `i/Fs`, via the same kernel `interp1`'s `"linear"` method uses) at the new instants `j/new_fs` — e.g. a 4-sample, 1 Hz ramp `[0,10,20,30]` (spanning t=0..3s) resampled to 2 Hz becomes the 7-sample `[0,5,10,15,20,25,30]`, still spanning t=0..3s — never a same-length signal with `Fs` merely swapped out (which would silently misstate the recorded duration). `signal.resample_to(new_fs)` also works, via the generic method-chain sugar. Wrap a plain vector first with `signal(data, Fs)` if it isn't already a `Signal`. |
| `interp2` | `interp2(x, y, Z, xq, yq, [method="bilinear"\|"nearest"])` | `x`: a length-`ncols` vector, the grid's COLUMN coordinates (strictly increasing); `y`: a length-`nrows` vector, the grid's ROW coordinates (strictly increasing); `Z`: an `(nrows, ncols)` matrix with `Z[i,j]` the value at `(y[i], x[j])` — `Matrix::get(row, col)`'s own indexing convention used everywhere else in this codebase, not a swapped axis order; `xq`/`yq`: paired query coordinates, either both numbers or both length-M vectors (`xq[k]`/`yq[k]` is query point `k` — not an implied meshgrid over every combination); `method` (optional string: `"bilinear"` default or `"nearest"`). 2-D grid interpolation (MATLAB's `interp2`): a query exactly at a grid coordinate returns that exact stored value, not an approximation; extrapolation beyond the grid is always on, matching `interp1`. Returns a number (if `xq`/`yq` are numbers) or a length-M vector (if they are vectors). |

`interp2` is the 2-D counterpart of `interp1` below — instead of a single `(x, y)` curve, it interpolates over a whole `(x, y, Z)` grid, the way a lookup table or a measured 2-D response surface would be sampled at an arbitrary point. The example below builds a tiny 2×3 grid, reads back an exact grid point (verifying no interpolation error is introduced there), then reads back the point exactly between all four corners (verifying the bilinear average).

```qu
x = [0, 1, 2]              # column coordinates
y = [0, 1]                 # row coordinates
Z = [1, 2, 3; 4, 5, 6]     # Z[i,j] at (y[i], x[j])
v_grid   = interp2(x, y, Z, 1, 1)         # exact grid point, no interpolation error
v_center = interp2(x, y, Z, 0.5, 0.5)     # bilinear average of the 4 surrounding corners
print("interp2 at grid point (x=1,y=1): {v_grid}")
print("interp2 at center (x=0.5,y=0.5): {v_center}")
```

## Interpolation

| Function | Signature | Description |
|---|---|---|
| `interp1` | `interp1(x, y, xq, [method="linear"\|"spline"\|"nearest"])` | `x`, `y`: matching length-N vectors (the known points, `x` strictly increasing); `xq`: a number or length-M vector, the query point(s); `method` (optional string). 1-D interpolation through `(x, y)` (MATLAB's `interp1`). Extrapolation beyond `x`'s range is always on — `"linear"` continues the boundary segment's own slope, `"spline"` extends the natural cubic spline's boundary segment, `"nearest"` just keeps returning the nearest endpoint's `y` — never a clamp or an error, matching what "interpolation *and* extrapolation" implies. Returns a number (if `xq` is a number) or a length-M vector (if `xq` is a vector). |
| `interpolate_at` | `interpolate_at(sig, t_query, [method="linear"\|"spline"\|"nearest"])` | `sig`: a length-N `Signal`; `t_query`: a number or length-M vector, query time(s) in seconds; `method` (optional string, `interp1`'s own three). A `Signal`-aware `interp1`: instead of an explicit `x`, the signal's OWN implicit time axis (`sig.t`, i.e. `i/Fs`) is used as `x` and `sig`'s samples as `y`. Shares `interp1`'s exact interpolation/extrapolation kernel, so the two never silently diverge in behavior. `sig.interpolate_at(t_query, [method])` also works via the generic method-chain sugar. Returns a number (if `t_query` is a number) or a length-M vector (if `t_query` is a vector) — **never** re-wrapped as a `Signal`: a `Signal` is a promise of uniform sampling at a known `Fs`, but the query times here are arbitrary caller-chosen instants with no guaranteed spacing, so there is no honest `Fs` to attach. |

#### Overloads: `interp1`

| Call | Extrapolation beyond `x`'s range |
|---|---|
| `interp1(x, y, xq)` / `interp1(x, y, xq, "linear")` | Continues the boundary segment's own slope. |
| `interp1(x, y, xq, "spline")` | Extends the natural cubic spline's boundary segment. |
| `interp1(x, y, xq, "nearest")` | Keeps returning the nearest endpoint's `y` — never a clamp or an error, matching what "interpolation *and* extrapolation" implies. |

The three methods agree everywhere `xq` sits inside `x`'s own range; they only diverge on how far past the edge they're willing to follow a curve. The example below queries `x=3.5`, one full step past the last known point at `x=3`, all three ways.

```qu
x = [0, 1, 2, 3]
y = [0, 1, 4, 9]
lin = interp1(x, y, 3.5)
sp  = interp1(x, y, 3.5, "spline")
near = interp1(x, y, 3.5, "nearest")
print("linear extrapolation at 3.5: {lin}")    # linear extrapolation at 3.5: 11.5
print("spline extrapolation at 3.5: {sp}")     # spline extrapolation at 3.5: 11.65
print("nearest extrapolation at 3.5: {near}")  # nearest extrapolation at 3.5: 9
```

`interpolate_at` saves you from manually building a signal's time axis just to call `interp1` on it — hand it a `Signal` and a query time (or times) in seconds and it reads `sig.t`/`sig`'s samples for you. The example below queries an interior point (ordinary interpolation), a point before the first sample and one after the last (extrapolation, using the boundary segment's own slope), and a vector of query times with the `"nearest"` method, both through the free-function and the method-chain spelling.

```qu
sig = signal([0, 10, 20, 30], 2)     # samples at t = 0, 0.5, 1.0, 1.5s
mid = interpolate_at(sig, 0.75)      # interior, halfway between samples 1 and 2
lo  = interpolate_at(sig, -0.5)      # extrapolated below t=0 via the boundary slope
hi  = sig.interpolate_at(2.0)        # extrapolated past the last sample
qs  = sig.interpolate_at([0.0, 0.5, 1.0], "nearest")
print("mid={mid}, lo={lo}, hi={hi}, qs={qs}")
```

`interp1(x, y, xq)`/`interpolate_at`'s existing extrapolation already covers what a separate `extrapolate_at` builtin would offer — there is no such function, and none is needed.

## Elementwise Apply (container-preserving)

| Function | Signature | Description |
|---|---|---|
| `apply` | `apply(x, f)` | `x`: a number, boolean, vector, matrix, or `Signal`; `f`: a one-argument function of a number returning a number — the function itself, or a `Str` naming one you defined. Returns the SAME container type and shape as `x` (a `Signal(xs, fs)` comes back as a new `Signal` at the same `fs`, a vector/matrix keeps its own shape, a bare number/boolean applies the function once). Elementwise map that PRESERVES `x`'s own container type — unlike `map(xs, f)` ([Collections, Strings & Data Frames](collections-strings.md)), which always returns a plain `List`, discarding any `Fs`/shape information on purpose. A builtin is accepted as a **value** (`apply(x, sin)`) but refused as a **quoted name** (`apply(x, "sin")`), the same rule `map`/`pmap` follow. Argument order is `(x, f)` — the value first, like every other higher-order builtin — so the receiver lands in `args[0]` and `x.apply(f)` works for free via the generic method-chain sugar. Every element's result must be numeric; a function returning something else is a clear error naming the offending element. Any other input type (`List`, `Table`, `Str`, ...) is a clear error — `map`/`pmap` already own the arbitrary-result/`List`-returning case. |

#### Overloads: `apply`

#### Case: scalar

`x` a bare number (or boolean). Applies `fnName` exactly once, returning a number.

```qu
double(v) := v * 2
n = apply(5, "double")
print("scalar: {n}")   # scalar: 10
```

#### Case: vector or matrix

`x` a `Vec`/`Mat`. Applies `fnName` elementwise, returning the same shape.

```qu
double(v) := v * 2
v = apply([1, 2, 3], "double")
print("vector: {v}")   # vector: [2, 4, 6]
```

#### Case: Signal

`x` a `Signal`. Applies `fnName` elementwise and re-wraps the result at the SAME `Fs` — the one case `map` can't reproduce, since `map` always returns a plain `List` and drops the sample rate.

```qu
double(v) := v * 2
sig = signal([1, 2, 3, 4], 8)
s = sig.apply("double")
print("signal: {s}")   # signal: signal(Fs=8) [2, 4, 6, 8]
```

`apply` is the one to reach for when you have your own user-defined transform and need it applied elementwise while KEEPING whatever container you started with — a `Signal`'s sample rate in particular, which `map` would silently drop. The example below defines a trivial doubling function and applies it to a `Signal`, printing the result to show the `Fs` survives the round trip.

```qu
double(v) := v * 2
sig = signal([1, 2, 3, 4], 8)
out = sig.apply("double")     # same Fs, genuinely transformed
print("apply(double): {out}")
```

## Time-Based Slicing

| Function | Signature | Description |
|---|---|---|
| `cut` | `cut(sig, t_start, t_end)` | `sig`: a length-N `Signal`; `t_start`, `t_end`: numbers (seconds, `t_start` >= 0 and `t_end` >= `t_start`). Returns a new `Signal` at the SAME `Fs`, shorter than `sig`. Trims `sig` to the time range `[t_start, t_end)` — half-open in TIME, the one range in the language that excludes its upper end: `t_end` is a floating-point instant, not an index, so "does it land exactly on a sample" has no reliable answer. Index slicing (`x[a:b]`) includes both ends. `t_start`/`t_end` round to the nearest sample via `sig`'s own `Fs` (`i = round(t*Fs)`, the exact inverse of `sig.t`'s `i/Fs`). A negative `t_start` or `t_end < t_start` is a clear error; `t_end` past `sig`'s actual duration clamps to the last sample rather than erroring (matching ordinary slice `hi`-clamping, e.g. `x[0:1000]` on a 10-element vector). Composes with the `@` self-mutation prefix like any other method chain: `@s.cut(1.0, 2.0)` needs no special-casing — it's an ordinary function under the hood. `cut` is a friendlier public name for exactly `signal_slice_time`'s own implementation (both names share one code path, so they can never silently diverge). |
| `signal_slice_time` | `signal_slice_time(sig, t0, t1)` | `sig`: a length-N `Signal`; `t0`, `t1`: numbers (seconds). Returns a new `Signal` at the same `Fs`. The original name for the same operation as `cut` above — kept as a working alias, not deprecated. |

`cut` is how you trim a `Signal` down to a time window of interest — say, the settling portion after a step, or a single cycle of a periodic waveform — without doing the sample-index arithmetic (`round(t*Fs)`) yourself. The example below trims a 10-sample, 10 Hz signal to `[0.5, 100.0)` seconds (the far end clamps to the last real sample rather than erroring), then uses the self-mutating `@s.cut(...)` form to trim `s` itself in place.

```qu
s = signal(0 to 9, 10)          # 10 samples at 10 Hz, t = 0.0, 0.1, ..., 0.9s
trimmed = cut(s, 0.5, 100.0)    # end clamps past the signal's duration
print("trimmed: {trimmed}")
@s.cut(0.2, 0.7)                 # self-mutating form: s = cut(s, 0.2, 0.7)
print("s after @cut: {s}")
```

### Which rate is used

A `Signal` carries its own `Fs`. Every spectral producer now reads it, and the
rule is the same for all of them:

| You pass | What is used |
|---|---|
| A `Signal`, no `fs` | The signal's own `Fs`. `welch(sig)` and `periodogram(sig)` no longer require a rate argument at all. |
| A `Signal` *and* a matching `fs` | That rate. Scripts that already pass the correct rate are unaffected. |
| A `Signal` *and* a different `fs` | **An error.** This is the temporal analogue of a shape mismatch: one of the two numbers is wrong, and computing an answer from either would be guessing which. |
| A plain vector and an `fs` | That rate — a vector carries none of its own. |
| A plain vector, no `fs` | The builtin's default where it has one (`spectrogram` uses 1), otherwise an error asking for a rate or for `signal(x, fs)`. |

The mismatch case cannot break correct code: a correct caller passes the rate
the signal already has. What it catches is the genuine bug — a PSD or
spectrogram computed at a rate the data was not sampled at, which until now
produced a plausible plot with a silently mislabelled axis.

`goertzel_freq` is the one exception to the "rate becomes optional" half: it
still requires `fs` positionally, because `goertzel_freq(sig, 100)` would
otherwise be ambiguous between a sample rate and the frequency to evaluate.
Its rate is still checked against the signal's.

## Frequency-Based Addressing

A `Signal` knows its own sample rate, so the transform of one can know its own
frequency axis. `fft(sig)`/`rfft(sig)` return a **`spectrum`**: the complex bins
plus the sampling contract they came from. That removes the step that causes
most DSP bugs — converting a physical frequency to a bin index by hand
(`round(f * N / fs)`) and then keeping that arithmetic in step with every
resample, zero-pad and window change.

`fft` on a *plain vector* still returns a plain complex vector, exactly as
before: a vector carries no rate, so there is nothing to propagate.

| Accessor | Returns | Description |
|---|---|---|
| `X.Fs` | number | The sample rate the spectrum was transformed from, in Hz. |
| `X.N` | number | The **transform length** — the number of time-domain samples. `fft(sig).N == sig.N`. For a half spectrum this is *not* the bin count. |
| `X.bins` | number | How many bins `X` actually holds: `N` for a full `fft`, `N/2 + 1` for a half `rfft`. |
| `X.df` | number | Bin spacing in Hz, `Fs/N`. Errors on an empty spectrum rather than reporting a meaningless `0`. |
| `X.nyquist` | number | The Nyquist frequency, `Fs/2`, in Hz. |
| `X.freq` | `Vec` | The frequency axis in Hz, one entry per bin (`k*Fs/N`) — computed, never hand-built. |
| `X.mag` | `Vec` | Bin magnitudes, `sqrt(re^2+im^2)`. A plain vector, so it can be sliced freely. |
| `X.phase` | `Vec` | Bin phases in radians, `atan2(im, re)`, in `(-pi, pi]`. |
| `X.norm` | string | How the producer normalised these bins. `"raw_transform"` for `fft`/`rfft`: bin `k` is the unnormalised DFT sum, so a unit-amplitude tone in an `N`-sample record reads `N/2`. Read-only — stamped at construction, never passed in. |

`X.norm` exists because `band_power` is only correct for one convention: it
reads raw bins and divides by `N^2`. Handed an already-normalised power
density it would return a plausible number computed from the wrong premise,
so it checks the tag rather than assuming. There is one convention today
because `fft`/`rfft` are the only producers; the tag is what makes a second
producer (a PSD estimator returning a spectrum) a visible difference at
runtime rather than an invisible assumption baked into every script written
before it landed. The analysis window and its ENBW are deliberately *not*
recorded: `fft` takes no window argument, so it cannot honestly claim one.

| Function | Signature | Description |
|---|---|---|
| `spectrum_at` | `spectrum_at(X, freq)` | `X`: a `spectrum`; `freq`: a number (Hz). Returns the single complex bin nearest that physical frequency (`round(freq/df)`, clamped to the available bins) — addressing the spectrum in Hz instead of by index. |
| `band_power` | `band_power(X, f0, f1)` | `X`: a `spectrum`; `f0`, `f1`: numbers (Hz, `f1 >= f0`). Returns the power in that frequency band by Parseval, normalised by `N^2` so a tone of amplitude `A` reads `A^2/2`. On a full spectrum each conjugate pair is counted once, since the pair is one physical tone. |
| `band_zero` | `band_zero(X, f0, f1)` | `X`: a `spectrum`; `f0`, `f1`: numbers (Hz, `f1 >= f0`). Returns a new `spectrum` at the same `Fs` and `N` with that band cleared — an ideal brick-wall notch. On a full spectrum it **also clears each bin's conjugate partner** (`N-k`), which is what keeps the inverse transform real; clearing only the positive-frequency half is the classic way to get a silently complex signal back out of `ifft`. |

There is deliberately **no "slice a band out of a spectrum" verb.** Slicing bins
would leave bin 0 of the result no longer at DC, so `.freq` would quietly start
lying about what the data is. `band_zero` keeps the axis intact, and `.mag`/
`.freq` hand back plain vectors that can be sliced safely.

```qu
fs  = 1000
t   = (0 to 999) / fs
x   = sin(2*pi*100*t) + 0.5*sin(2*pi*300*t)
sig = signal(x, fs)

X = fft(sig)
print("df = {X.df} Hz, Nyquist = {X.nyquist} Hz")
print("power at 100 Hz: {band_power(X, 90, 110)}")     # 0.5  = 1.0^2/2
print("power at 300 Hz: {band_power(X, 290, 310)}")    # 0.125 = 0.5^2/2

clean = ifft(band_zero(X, 250, 350))                    # notch out the 300 Hz tone
print("residual imaginary part: {max(abs(imag(clean)))}")   # ~1e-16, still real
```

### Windows (design *and* generation)

`hann`, `hamming`, `blackman`, and `kaiser` are used in two distinct places in the interpreter: as **generator functions** callable directly by name (below, returning the window samples as a plain `Vec`), and internally as the **window option** for `fir1(..., window="hamming")`, `welch(..., window="hann")`, and `periodogram(..., window="hann")` (passed as a style-argument string, not called as a function). Both call sites share the same underlying `raised_cosine_window`/`kaiser_window` Rust implementations.

| Function | Signature | Description |
|---|---|---|
| `hann` | `hann(n)` | `n`: a number (integer window length). Returns a length-`n` real vector. Raised-cosine window, `w[i] = 0.5*(1 - cos(2*pi*i/(n-1)))`. Symmetric convention (denominator `n-1`, MATLAB/SciPy `sym=True`); `w[0] == w[n-1] == 0` exactly. |
| `hamming` | `hamming(n)` | `n`: a number (integer window length). Returns a length-`n` real vector. Same raised-cosine family as `hann` but with coefficients `0.54 - 0.46*cos(...)`, chosen to minimize the nearest side-lobe (at the cost of slower roll-off). Endpoints are `0.08` exactly, not zero. |
| `blackman` | `blackman(n)` | `n`: a number (integer window length). Returns a length-`n` real vector. Standard 3-term Blackman window, `a0 - a1*cos(...) + a2*cos(2*...)` with `a0=0.42, a1=0.5, a2=0.08` (textbook "exact" coefficients). Endpoints are `0.0` exactly. |
| `kaiser` | `kaiser(n, beta)` | `n`: a number (integer window length); `beta`: a number, required second positional argument (no default — it fundamentally changes the main-lobe-width/side-lobe-level tradeoff). Returns a length-`n` real vector, `w[i] = I0(beta*sqrt(1-((2i/(n-1))-1)^2)) / I0(beta)`. Center sample is always `1.0` for any `beta`. |

### Time & Frequency Axes

| Function | Signature | Description |
|---|---|---|
| `linspace` | `linspace([a=0], [b=1], [n=50])` | `a`, `b` (optional numbers): the inclusive endpoints; `n` (optional number, integer count). Returns a length-`n` real vector, `n` linearly spaced points from `a` to `b` inclusive — the standard companion for building a time or frequency axis to plot alongside a generated/transformed signal. |
| `logspace` | `logspace([a=0], [b=1], [n=50])` | `a`, `b` (optional numbers, decade exponents); `n` (optional number, integer count). Returns a length-`n` real vector, `n` logarithmically spaced points, `10^linspace(a, b, n)` — used for frequency axes in Bode-style plots and rLKK's default DRT grid. |

## Equivalent Circuits

A circuit is a value. You build it from elements, combine them in series and
parallel, and ask for its impedance over a frequency sweep — instead of
writing out the algebraically pre-solved closed form by hand.

That hand-solving is what this replaces. A Randles circuit is usually written
as `Rs + Rct/(1 + jwRctCdl)`, which is `Rs` in series with `Rct` parallel
`Cdl`, with the parallel branch solved on paper. Fine for one circuit; it does
not survive a library of them, and every new topology is a fresh chance to
drop a factor.

```qu
randles = series(resistor(0.2), parallel(resistor(0.01), capacitor(100e-6)))
Z = impedance(randles, logspace(-2, 5, 200))     # frequencies in Hz
nyquist(Z)
```

A circuit is a **model** and carries no frequency axis of its own —
`impedance(c, freqs)` is what turns it into data. That separation is
deliberate: the same circuit on two different sweeps is the same circuit.

### Elements

| Function | Signature | Impedance |
|---|---|---|
| `resistor` | `resistor(R)` | `R` |
| `capacitor` | `capacitor(C)` | `1/(jwC)` |
| `inductor` | `inductor(L)` | `jwL` |
| `cpe` | `cpe(Q, n)` | `1/(Q (jw)^n)` — constant-phase element. `n=1` is a capacitor, `n=0` a resistor, `n=0.5` a Warburg. |
| `warburg` | `warburg(Aw)` | `Aw (1-j)/sqrt(w)` — semi-infinite diffusion, a constant −45° phase at every frequency. |
| `warburg_short` | `warburg_short(Rw, tau)` | `Rw tanh(x)/x`, `x = sqrt(jw tau)` — finite length, transmissive boundary. Spec-string name `Ws`. |
| `warburg_open` | `warburg_open(Rw, tau)` | `Rw coth(x)/x`, `x = sqrt(jw tau)` — finite length, reflecting boundary. Spec-string name `Wo`. |
| `gerischer` | `gerischer(Zg, k)` | `Zg/sqrt(k + jw)` — a coupled chemical reaction. |
| `porous` | `porous(Rp, Q, n)` | `sqrt(Rp Zi)/tanh(sqrt(Rp/Zi))`, `Zi = 1/(Q (jw)^n)` — de Levie porous electrode. |
| `havriliak_negami` | `havriliak_negami(Rh, tau, a, g)` | `Rh/(1 + (jw tau)^a)^g` |

### Composition and evaluation

| Function | Signature | Description |
|---|---|---|
| `series` | `series(a, b, ...)` | Two or more circuits in series; impedances add. |
| `parallel` | `parallel(a, b, ...)` | Two or more circuits in parallel; admittances add. An ideal short in any branch shorts the block. |
| `impedance` | `impedance(c, freqs)` | `c`: a circuit; `freqs`: frequencies in **Hz**, not rad/s. Returns a complex vector, one impedance per frequency. A zero or negative frequency is an error rather than an infinity: at DC a capacitor's impedance is unbounded and a Warburg's is undefined, and returning `inf`/`NaN` into a spectrum hides the mistake instead of reporting it. |
| `circuit` | `circuit(spec, params)` | Builds a circuit from a **spec string** and a flat parameter vector. |

### Spec strings

`circuit("R-p(R,C)", [0.2, 0.01, 100e-6])` builds the same Randles circuit as
the `series`/`parallel` form above. The grammar is `A-B-C` for series and
`p(A,B,C)` for parallel, with each leaf an element letter plus an optional
name — `Rs`, `Rct` and `R1` are all resistors, and the name is for the reader.

| Name | Element | Params |
|---|---|---|
| `R` `C` `L` `W` | resistor, capacitor, inductor, Warburg | 1 |
| `Q` `G` | CPE, Gerischer | 2 |
| `Ws` `Wo` | finite-length Warburg, short / open boundary | 2 |
| `P` | porous | 3 |
| `H` | Havriliak-Negami | 4 |

Element names are matched **longest-first** — two characters, then one. That
is what lets `Ws` be an element at all: `Ws` was already a valid spelling
before it was one (a `W` with instance tag `s`), so the boundary between
element and tag cannot be "always one character". `W1` still reads as a
Warburg named `1`, because `W1` is not an element name.

`T` and `O` were the original spellings of `Ws` and `Wo` and are still
**read** as deprecated aliases, so existing spec strings keep working. They
are never **written**: a round trip normalises `T1` to `Ws`, so the
deprecation retires instead of persisting.

**Parameters are consumed in left-to-right leaf order**, and that ordering is
the documented contract — it is what makes a parameter vector interchangeable
with the `papers/ecm-pf` Qu and Python implementations, whose 40-topology
cross-language check therefore also checks this code.

A parameter vector of the wrong length is an error in **both** directions.
Too few is obvious; too many is rejected rather than truncated, because
silently ignoring the tail would fit a different circuit than the one written.

```qu
c = circuit("R-p(Q,R)-Ws", [0.2, 1e-5, 0.8, 0.01, 5.0, 2.0])
print("{c}")                   # circuit("R-p(Q,R)-Ws") [0.2, 1e-5, 0.8, 0.01, 5, 2]
```

Circuits compare with `==` by topology **and** component values. There is no
order on them, so `<` is an error rather than a guess.

> is an absolute standard; never rank nested topologies by chi-squared, since

## Impedance Spectroscopy (rLKK)

A port of Ahmed Yousef Kallel's own published method (Kallel & Kanoun, "Regularized linear Kramers-Kronig transform for consistency check of noisy impedance spectra with logarithmic frequency distribution", IWIS 2021), shipped 2026-08-23. `Z` is a complex impedance spectrum (a length-N `CVec`), `freqs` its matching length-N frequency vector in Hz.

| Function | Signature | Description |
|---|---|---|
| `rlkk_reconstruct` | `rlkk_reconstruct(Z, freqs, [lambda=1e-4], [fx=])` | `Z`: a length-N complex vector (`CVec`); `freqs`: a length-N real vector (Hz); `lambda` (optional number): regularization strength, larger tolerates noisier data at the cost of fitting detail; `fx` (optional length-M real vector, Hz): overrides the default DRT frequency grid (`logspace(-8, 8, 160)`, i.e. M=160). Returns a `Model` (kind `"rlkk"`) with fields `z` (a length-N `CVec`, the reconstructed spectrum) and `gamma` (a length-M real vector, the fitted DRT coefficients). Fits the regularized Distribution of Relaxation Times (DRT) and reconstructs `Z` from it. |
| `rlkk_validate` | `rlkk_validate(Z, freqs, [lambda=1e-3], [threshold=2.0])` | `Z`: a length-N complex vector (`CVec`); `freqs`: a length-N real vector (Hz); `lambda` (optional number); `threshold` (optional number, percent). Returns a `Model` (kind `"rlkk_validation"`) with fields `valid` (a boolean, true iff every point's percent residual is under `threshold`), `residuals` (a length-N real vector, percent), `max_residual` (a number). Checks `Z` against its own rLKK reconstruction. |
| `rlkk_extrapolate` | `rlkk_extrapolate(Z, freqs, target_freqs, [lambda=1e-4])` | `Z`: a length-N complex vector (`CVec`); `freqs`: a length-N real vector (Hz); `target_freqs`: a length-M real vector (Hz), which may extend beyond the measured band; `lambda` (optional number). Returns a single length-M `CVec`, not a model. Refits the DRT from `(Z, freqs)` and evaluates it at `target_freqs` — for reconstructing truncated/incomplete measurements. |

`nyquist(Z)`, `bode_magnitude(Z, freqs)`, and `bode_phase(Z, freqs)` (documented above under [Spectral Analysis](#spectral-analysis)) are the standard plots for visualizing rLKK inputs and outputs.

## Worked Examples

### FFT and magnitude spectrum

`fft`/`fftc` is the entry point for almost every frequency-domain task in this chapter: given a real time-domain record, it returns the complex spectrum that everything else (magnitude, phase, peak-finding, filtering analysis) is read off of. The example below builds a two-tone signal (80 Hz and 300 Hz), transforms it, keeps only the positive-frequency half (the negative half is redundant for a real input), and plots magnitude against a matching Hz axis built with `linspace`. It then uses `find_peaks` to confirm both tones are recovered at their expected frequencies.

```qu
Fs = 1000
n = 0:1:1023
t = n / Fs
x = sin(2*pi*80*t) + 0.5*sin(2*pi*300*t)

X = fftc(x)
mag = abs(X)[0:512]                 # positive-frequency half
freqs = linspace(0, Fs/2, 512)
peaks = find_peaks(mag, min_height=max(mag)*0.2, min_distance=5)
print("tones at: {freqs[peaks]} Hz")
plot(freqs, mag)
xlabel("frequency (Hz)")
```

### Butterworth design, batch and streaming filtering

`butter` is the go-to when you just need "a lowpass/highpass/bandpass/notch filter of about this order and cutoff" without worrying about ripple — its cascade-of-second-order-sections (`sos`) form stays numerically well-behaved even at higher orders, unlike a raw transfer-function `[b, a]` pair. The example below designs a 100 Hz lowpass and a 45-55 Hz mains-hum notch, applies the lowpass both causally (`sosfilt`, real-time-safe but phase-lagged) and zero-phase (`filtfilt`, offline-only but no phase distortion), checks both designs are stable, and reads the lowpass's frequency response with `freqz`.

```qu
fs     = 1000
t      = (0 to 999) / fs
signal = sin(2 * pi * 50 * t) + 0.5 * sin(2 * pi * 220 * t) + 0.1 * randn(1000, seed = 2)
lp = butter(4, "low", 100, fs)             # 4th-order lowpass, 100 Hz cutoff
notch = butter(2, "notch", [45, 55], fs)   # removes 45-55 Hz mains hum

filtered = sosfilt(lp, signal)             # causal, one pass
zero_phase = filtfilt(lp, signal)          # zero-phase, double effective order
print("lp is stable: {is_stable(lp)}, notch is stable: {is_stable(notch)}")

H = freqz(lp, 512)
plot(linspace(0, fs/2, 512), mag2db(abs(H)))
```

### Spectrogram of a time-varying signal

Where a single `fft` gives one frequency snapshot of an entire record, `spectrogram` shows how that spectrum evolves over time — the standard tool for a signal whose content changes mid-record (a chirp, a burst, a spoken word). It slides a windowed FFT along `x` and renders the resulting magnitude-vs-time-vs-frequency data as a heatmap. The example below renders two stationary tones (80 Hz and 300 Hz, present for the whole record) as two horizontal bands.

```qu
Fs = 1000
n = 0:1:1023
t = n / Fs
x = sin(2*pi*80*t) + sin(2*pi*300*t)
spectrogram(x, 128, 32, Fs)
title("Two stationary tones")
xlabel("time (s)")
ylabel("frequency (Hz)")
```

### Nonlinear curve fitting

`curve_fit` is for the common case where a model is nonlinear in its parameters (so ordinary least-squares regression doesn't apply) but a reasonable starting guess is available — fitting an exponential decay's rate and amplitude, a resonance's center frequency and width, and so on. The example below generates noisy samples of a known exponential decay `a * exp(-b * x)`, fits the same functional form back from a `[1, 1]` starting guess, and prints how closely the recovered `a`/`b` match the values (3, 0.7) the data was generated from.

```qu
model(x, p) := p[0] * exp(-p[1] * x)
xdata = linspace(0, 5, 50)
ydata = 3 * exp(-0.7 * xdata) + 0.02 * randn(50, seed=1)   # noisy samples of a=3, b=0.7
fit = curve_fit("model", xdata, ydata, [1, 1])   # initial guess [1, 1]
print("a = {fit.params[0]}, b = {fit.params[1]}, cost = {fit.cost}")
```

### rLKK reconstruction and validation

`rlkk_reconstruct` and `rlkk_validate` are the two halves of a self-consistency check on measured impedance data: fit a smooth Distribution of Relaxation Times to the spectrum, reconstruct the spectrum from that fit, and see how far the reconstruction departs from the original. A departure beyond the tolerance signals a measurement that violates the Kramers-Kronig relations (non-causal, non-linear, or drifting during acquisition) rather than genuine device behavior. The example below builds a clean synthetic RC impedance (so the reconstruction is expected to be near-exact), validates it, and draws the standard Nyquist view.

```qu
freqs = logspace(0, 4, 20)
R = 100
C = 1e-6
w = 2 * pi * freqs
Z = R / (1 + 1j * w * R * C)         # a simple RC impedance, as measured data

fit = rlkk_reconstruct(Z, freqs, lambda=1e-4)     # fit.z, fit.gamma
v = rlkk_validate(Z, freqs, lambda=1e-3, threshold=2.0)
if v.valid
    print("measurement is causal/linear/stable within {v.max_residual}%")
else
    print("bad points: {where(abs(v.residuals) > 2.0)}")
end

nyquist(Z)   # Re(Z) vs -Im(Z), the standard EIS view
```

### Direct DFT, inverse DFT, and Goertzel

`dft`/`idft` are the textbook O(n²) reference pair, kept around specifically to validate the fast implementations (`fft`/`rfft`) against on new code, rather than for everyday use. `goertzel`/`goertzel_freq` take the opposite approach — evaluating a single DFT bin (or a single Hz frequency) in O(n), which is the right tool when only a handful of known tones matter and paying for a whole FFT would be wasteful. `irfft` inverts a real-optimized half-spectrum back to a real signal. It has a second name, `fftr`, which is **deprecated**: it is the inverse transform sitting one row away from `rfft`, the forward one, so the pair reads backwards and gets used backwards. The example below round-trips a 100 Hz tone through `fft`/`idft`, checks `goertzel`/`goertzel_freq` agree on the same tone's bin, and round-trips `rfft`/`irfft`, printing the residual error of each round trip.

```qu
fs = 1000
n = 0:1:63
t = n / fs
x = sin(2*pi*100*t)

X = fft(x)
xr = idft(X)
print("idft roundtrip max err: {max(abs(xr - x))}")

k100 = 100 * length(x) / fs        # bin index equivalent to 100 Hz
bin100 = goertzel(x, k100)
print("goertzel magnitude at bin {k100}: {abs(bin100)}")
same = goertzel_freq(x, fs, 100)   # the Hz-parameterized convenience form
print("goertzel_freq agrees: {abs(same - bin100) < 1e-9}")

half = rfft(x)
back = irfft(half, 64)
print("rfft/irfft roundtrip max err: {max(abs(back - x))}")
```

### Level conversions and window functions

`mag2db`/`db2mag`/`pow2db`/`db2pow` are the small conversions that come up constantly when reporting amplitudes and powers on a decibel scale, and being separate named functions (rather than one ambiguous `db()`) avoids the classic factor-of-10-vs-20 mixup between amplitude and power ratios. `hamming`/`blackman`/`kaiser` (and `hann`, not shown here) are the window generators used both standalone and internally by `fir1`/`welch`/`periodogram`. `logspace` rounds this out as the standard way to build a log-spaced frequency axis. The example below exercises one of each.

```qu
amp = db2mag(-6)     # amplitude ratio for -6 dB
pow = db2pow(-3)     # power ratio for -3 dB
print("db2mag(-6) = {amp}, db2pow(-3) = {pow}")

w_hamming = hamming(8)
w_blackman = blackman(8)
w_kaiser = kaiser(9, 5)             # beta=5, odd length so there's an exact center sample
print("hamming[0] = {w_hamming[0]}, blackman[0] = {w_blackman[0]}, kaiser center = {w_kaiser[4]}")

f = logspace(0, 3, 4)               # 1, 10, 100, 1000 -- a log-spaced frequency axis
print("logspace(0,3,4) = {f}")
```

### Welch and periodogram PSD estimates

`welch` and `periodogram` both estimate a signal's power spectral density — where it lands in frequency, not just a snapshot magnitude spectrum — but trade off differently: `periodogram` uses the whole record as one segment (higher frequency resolution, noisier estimate), while `welch` averages many shorter overlapping segments (coarser resolution, much less variance). The example below estimates the PSD of a 100 Hz tone buried in noise both ways and confirms each estimate's spectral peak lands near 100 Hz.

```qu
fs = 1000
n = 0:1:1023
t = n / fs
x = sin(2*pi*100*t) + 0.05 * randn(1024, seed=1)

psd_w = welch(x, fs, nperseg=256)
f_w = linspace(0, fs/2, length(psd_w))
peak_w = find_peaks(psd_w, min_height=max(psd_w)*0.5)
print("welch peak near {f_w[peak_w[0]]} Hz")

psd_p = periodogram(x, fs)          # single-segment special case of welch
f_p = linspace(0, fs/2, length(psd_p))
peak_p = find_peaks(psd_p, min_height=max(psd_p)*0.5)
print("periodogram peak near {f_p[peak_p[0]]} Hz")
```

### Elliptic/Chebyshev/FIR filter design, application, and analysis

Beyond `butter`, the IIR family adds `ellip` and `cheby1`/`cheby2` for when a steeper transition band is worth trading for passband/stopband ripple, and `fir1`/`firls` cover the FIR side (always stable, linear phase, but needing a higher order for the same rolloff). This example designs one of each IIR type at matching specs, applies an FIR lowpass two equivalent ways (`filter_ba` and its `lfilter` alias), designs a least-squares FIR from explicit band edges, and finishes with the filter-analysis tools (`group_delay`, `poles`, `fvtool`, `pzplot`) that inspect a design instead of just applying it.

```qu
fs = 1000
ep = ellip(4, 1, 40, "low", 100, fs)
c1 = cheby1(4, 1, "low", 100, fs)
c2 = cheby2(4, 40, "low", 100, fs)
print("ellip stable: {is_stable(ep)}, cheby1 stable: {is_stable(c1)}, cheby2 stable: {is_stable(c2)}")

fir = fir1(6, 100, kind="low", window="hamming", fs=fs)
b = fir.b
a = [1]
n = 0:1:255
t = n / fs
x = sin(2*pi*40*t) + sin(2*pi*300*t)
y  = filter_ba(b, a, x)
y2 = lfilter(b, a, x)               # lfilter is the same builtin under another name
print("filter_ba/lfilter agree: {max(abs(y - y2)) < 1e-12}")

lsq = firls(20, [0, 0.2, 0.3, 1.0], [1, 1, 0, 0])   # low-pass band edges/response
print("firls taps: {length(lsq.b)}")

gd = group_delay(fir, 256)
print("FIR group delay (should be ~order/2=3): {gd[10]}")
print("ellip filter has {length(poles(ep))} poles")

ep.fvtool()   # 2x2 magnitude/phase/group-delay/impulse-response figure
pzplot(ep)    # pole-zero plot with the unit circle and stability verdict
```

### Sigma-delta modulation and time-based slicing

`sigma_delta` turns a smooth signal into a 1-bit stream that still encodes the original waveform in its average behavior — the building block of 1-bit DACs and of "DIBS-ΔΣ" style excitation signals. `signal_slice_time` (the original name for `cut`, shown here for completeness) trims a `Signal` to a time window. Neither depends on the other; they're grouped here simply because both examples are short. The example below quantizes a 50 Hz tone and confirms the output only ever takes the values ±1, then slices a 10-sample signal down to `[0.2, 0.6)` seconds.

```qu
fs = 1000
tone = sine(50, fs, 20)
bits = sigma_delta(tone)            # 1-bit noise-shaping quantizer
print("sigma_delta output range: [{min(bits)}, {max(bits)}]")

s = signal(0 to 9, 10)
trimmed = signal_slice_time(s, 0.2, 0.6)   # same operation `cut` is the friendlier name for
print("signal_slice_time(0.2, 0.6) -> {trimmed}")
```

### Extrapolating an impedance spectrum with rLKK

Real impedance measurements often don't cover the full frequency range a later analysis needs — an instrument might be limited at the low or high end while the physics of interest extends beyond it. `rlkk_extrapolate` refits the same regularized DRT model `rlkk_reconstruct` uses, then evaluates it at whatever frequencies are asked for, including ones outside the originally measured band. The example below extrapolates a synthetic RC impedance measured over 1 Hz-10 kHz out to a wider 0.1 Hz-100 kHz target grid.

```qu
freqs = logspace(0, 4, 20)
R = 100
C = 1e-6
w = 2 * pi * freqs
Z = R / (1 + 1j * w * R * C)         # a simple RC impedance, as measured data

target = logspace(-1, 5, 10)         # extends past the measured band on both sides
Z_ext = rlkk_extrapolate(Z, freqs, target, lambda=1e-4)
print("extrapolated {length(Z_ext)} points, first = {Z_ext[0]}, last = {Z_ext[9]}")
```

### ADC signal-quality metrics: THD, SNR, SINAD, SFDR, ENOB

`thd`, `snr`, `sinad`, `sfdr`, and `enob` (see [More functions](#more-functions) below for their full parameter list, including the `tones=`/`bins=`/`leak=` options for multisine excitations) all characterize how cleanly a sampled record represents its input, each from a different angle: distortion power, noise power, the combination of both, the worst single spurious tone, and the resolution a converter is actually delivering. `sinad(x)` alone returns the whole breakdown as one record, which is usually more convenient than calling each metric separately. The example below builds a coherently-sampled tone with a known third-harmonic distortion component and background noise, reads off every metric, and compares the measured ENOB against `enob_estimate`'s closed-form prediction for an ideal 12-bit converter.

```qu
fs = 1000
n = 0:1:1023
t = n / fs
f0 = 99 * fs / 1024          # exactly 99 cycles in the record -- coherent sampling
clean = sin(2*pi*f0*t)
x = clean + 0.01 * sin(2*pi*3*f0*t) + 0.001 * randn(1024, seed=3)

r = sinad(x)     # full breakdown: r.sinad, r.enob, r.snr, r.thd, r.sfdr
print("THD  = {thd(x)} dB")
print("SNR  = {snr(x)} dB")
print("SINAD = {r.sinad} dB, ENOB = {r.enob} bits, SFDR = {sfdr(x)} dB")
print("ENOB (from thd/sinad breakdown) = {enob(x)} bits")

# closed-form estimates: what an ideal N-bit converter would show for a
# signal of a given crest factor, no record needed -- the number sinad(x)
# above is checked against. Signature is (bits, crest_factor).
est_sinad = sinad_estimate(12, sqrt(2))    # 12-bit ADC, sine-wave crest factor
est_enob  = enob_estimate(12, sqrt(2))
print("ideal 12-bit ADC: SINAD = {est_sinad} dB, ENOB = {est_enob} bits")
```

### Autocorrelation and the Hurst exponent

`acf` measures how similar a signal is to a delayed copy of itself at each lag — the standard way to find a periodic signal's own period (the lag at which correlation drops off, or where it comes back up for a periodic component) without a full spectral analysis. `hurst_exponent` characterizes a different property, long-range dependence: 0.5 means a random walk, above 0.5 persistent/trending behavior, below 0.5 mean-reverting behavior. The example below computes the autocorrelation of a noisy 20 Hz tone and finds where it first drops below `1/e`, then contrasts the Hurst exponent of that same periodic-plus-noise signal against a genuine random walk (`cumsum` of white noise).

```qu
fs = 1000
n = 0:1:511
t = n / fs
x = sin(2*pi*20*t) + 0.2*randn(512, seed=4)

r = acf(x, max_lag=50)
below = find_peaks(-abs(r - 1/e))
print("acf[0] = {r[0]}, acf drops below 1/e near lag {below[0]}")

h_tone = hurst_exponent(x)
h_walk = hurst_exponent(cumsum(randn(512, seed=5)))
print("hurst (periodic+noise) = {h_tone}, hurst (random walk) = {h_walk}")
```

### Periodic and calendar profiles

`periodic_profile` folds a long record onto one arbitrary cycle length and summarizes each phase bin with a chosen statistic (`stat="mean"`, `"std"`, `"var"`, `"hurst"`, or `"sad"`) — the tool for asking "does this disturbance repeat on a schedule?" without a full spectral analysis. `minutely_profile`/`hourly_profile`/`daily_profile`/`monthly_profile` are fixed presets of the same fold, at the cycle lengths their names suggest (1 hour in 60 minute-of-hour bins, 1 day in 24 hour-of-day bins, 1 week in 7 day-of-week bins, 1 Julian year in 12 equal-width bins), so a caller doesn't have to spell out `period_seconds`/`n_bins` for the common calendar cases. The five examples below each construct a synthetic signal with a known repeating pattern at the relevant timescale (a periodic spike, a day/night cycle, a burst of per-hour activity, a weekday/weekend split, an annual sinusoid) and confirm the profile recovers it.

```qu
## periodic_profile: a burst that recurs every 2 seconds, folded onto one cycle
fs = 200
n = 0:1:1999          # 10 seconds
t = n / fs
x = 0.05*randn(2000, seed=6)
x = x + where((t mod 2.0) < 0.1, 1.0, 0.0)   # a short spike once per 2s cycle
prof = periodic_profile(x, fs, 2.0, 20, stat="mean")
print("periodic_profile bins: {length(prof)}, spike bin mean = {max(prof)}, baseline ~ {prof[10]}")

## hourly_profile: a day/night sinusoid, sampled once per minute over 2 days
fs_h = 1.0/60.0
n_h = 0:1:2879        # 2 days at 1 sample/min
t_h = n_h / fs_h
hour_of_day = (t_h/3600) mod 24
xh = sin(2*pi*hour_of_day/24) + 0.1*randn(2880, seed=7)
hp = hourly_profile(xh, fs_h, stat="mean")
print("hourly_profile: {length(hp)} bins, quietest hour idx = {find_peaks(-hp)[0]}")

## minutely_profile: activity concentrated in the first 5 minutes of each hour
fs_m = 1.0
n_m = 0:1:10799       # 3 hours at 1 Hz
t_m = n_m / fs_m
minute_of_hour = (t_m/60) mod 60
xm = where(minute_of_hour < 5, 1.0, 0.0) + 0.05*randn(10800, seed=8)
mp = minutely_profile(xm, fs_m, stat="mean")
print("minutely_profile: {length(mp)} bins, busiest minute idx = {find_peaks(mp)[0]}")

## daily_profile: weekday/weekend pattern, one sample per hour over 3 weeks
fs_d = 1.0/3600.0
n_d = 0:1:503         # 21 days at 1 sample/hour
t_d = n_d / fs_d
day_of_week = (t_d/86400) mod 7
xd = where(day_of_week < 5, 1.0, 0.0) + 0.05*randn(504, seed=9)   # higher on weekdays
dp = daily_profile(xd, fs_d, stat="mean")
print("daily_profile: {length(dp)} bins (0=day0..6), values = {dp}")

## monthly_profile: an annual cycle, one sample per day over ~2 years
fs_mo = 1.0/86400.0
n_mo = 0:1:729        # 2 years at 1 sample/day
t_mo = n_mo / fs_mo
xmo = sin(2*pi*t_mo/31557600) + 0.05*randn(730, seed=10)
mop = monthly_profile(xmo, fs_mo, stat="mean")
print("monthly_profile: {length(mop)} bins, values = {mop}")
```

### Two things worth looking at

A filter's magnitude response, on a log frequency axis where a decade of
roll-off is a straight line:

```qu
fs = 1000
b = butter(4, "low", 100, fs)
h = freqz(b, 512)
f = linspace(0, fs / 2, 512)
plot(f, mag2db(abs(h)), color = "#4169e1", width = 2)
xscale("log")
ylim(-80, 5)
xlabel("frequency (Hz)")
ylabel("magnitude (dB)")
title("4th-order Butterworth, 100 Hz cutoff")
```

Fourth order is 80 dB per decade, and the plot is the cheapest way to check
that the filter you designed is the filter you meant.

And a spectrum, which is what most of this chapter exists to produce:

```qu
fs = 2000
t = linspace(0, 1, fs)
x = sin(2 * pi * 120 * t) + 0.4 * sin(2 * pi * 350 * t) + 0.2 * randn(fs, seed = 4)
X = rfft(x)
f = linspace(0, fs / 2, len(X))
print("largest peak at {round(f[argmax(abs(X))], 1)} Hz")
plot(f, mag2db(abs(X)), color = "#4169e1")
xlabel("frequency (Hz)")
ylabel("magnitude (dB)")
title("two tones in noise")
```

`rfft` returns the half-spectrum, which is all a real signal has; `fftr` is
not its forward partner but an alias for `irfft`, the inverse.

## Reflection and Matching

How much of a wave a load sends back, and the quantities engineers quote for
it. `smith` already drew this — these are the same arithmetic as *values*, so
a script can read the number the chart is plotting. Both call one
implementation (`qu_core::rf`), so the plot and the number cannot drift apart.

All four derived quantities take a **reflection coefficient**, not an
impedance. `vswr(reflection_coefficient(Z))` is one call longer than
`vswr(Z, z0=50)` would be, and it says which model it is in; the alternative
is a function whose meaning changes silently depending on whether a keyword
was passed.

Scalars and vectors both work: a bare load gives a bare answer, a swept
vector gives a vector, which is the shape measured data arrives in.

| Function | Signature | Description |
|---|---|---|
| `reflection_coefficient` | `reflection_coefficient(z, [z0=50])` | `z`: an impedance — real or complex, scalar or vector (ohms); `z0` (optional number, default 50): the real reference impedance. Returns `Γ = (z - z0)/(z + z0)`, complex. Errors at `z = -z0`, where `Γ` is genuinely undefined rather than merely large (impossible for a passive load). |
| `impedance_from_reflection` | `impedance_from_reflection(g, [z0=50])` | `g`: a reflection coefficient, scalar or vector; `z0` (optional number, default 50). Returns `z = z0(1 + Γ)/(1 - Γ)`, the exact inverse. Errors at `Γ = 1`, an ideal open. |
| `vswr` | `vswr(g)` | `g`: a reflection coefficient. Returns `(1 + \|Γ\|)/(1 - \|Γ\|)`. A perfect match is exactly `1`; total reflection is `inf`, which is the true value rather than a large stand-in. `\|Γ\| >= 1` (an active or mismeasured load) returns `inf` rather than the **negative** number the unguarded formula produces. |
| `return_loss` | `return_loss(g)` | `g`: a reflection coefficient. Returns `-20 log10 \|Γ\|` in dB, **positive** for a passive load — the engineering convention in which "20 dB return loss" means well matched. A perfect match is `inf`. |
| `mismatch_loss` | `mismatch_loss(g)` | `g`: a reflection coefficient. Returns `-10 log10(1 - \|Γ\|²)` in dB: the incident power not delivered to the load. Zero for a perfect match. |

`z0` is a **real** reference impedance. Complex-`z0` (power-wave) definitions
exist and are not what these compute; with a real `z0` the voltage-wave and
power-wave definitions coincide, which is why the simpler one is safe here.

```qu
g = reflection_coefficient(100)         # 100 ohm on a 50 ohm line
print("gamma = {g}")                     # 0.333333
print("VSWR  = {vswr(g)}")                # 2
print("RL    = {return_loss(g)} dB")      # 9.542425

swept = reflection_coefficient([50, 100, 0, 25])
print("VSWR swept = {vswr(swept)}")       # [1, 2, inf, 2]  -- the short is inf

smith([50, 100, 25], z0=50)               # same arithmetic, drawn
```
