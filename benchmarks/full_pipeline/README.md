# Full signal-processing pipeline benchmark

A chained, realistic workflow — not isolated kernels (`matty_suite/`) or a
single load+filter step (`csv_filters/`). Seven stages, each feeding the
next, the shape of a real analysis script:

1. **load** — `read_csv`
2. **clean** — remove DC offset (`x - mean(x)`)
3. **filter** — Butterworth bandpass (order 4, 200–1000 Hz), causal
4. **spectral** — `rfft` magnitude spectrum + peak-finding
5. **time-frequency** — spectrogram (STFT magnitude) + spectral entropy
6. **feature extraction** — short-time energy, total energy, RMS, crest factor
7. **export** — write extracted features back to CSV

Run:

```bash
qu run benchmarks/full_pipeline/bench.qu
python benchmarks/full_pipeline/bench.py
```

## Dataset

200,000 samples at `Fs = 10 kHz` (20 s), three tones (60 Hz, 440 Hz,
1800 Hz — the bandpass keeps only the 440 Hz tone) plus noise and a DC
offset — `pipeline_signal.csv` is gitignored, regenerated by each script's
own run.

## Results (this machine, single trials — not statistically rigorous)

| Stage | Qu | Python (pandas + scipy) |
|---|---|---|
| load | 0.012–0.016 s | 0.037 s |
| clean | 0.0005–0.0006 s | 0.0005 s |
| filter | 0.0017 s | 0.005 s |
| spectral | 0.006–0.007 s | 0.002 s |
| time-frequency | 0.008–0.010 s | 0.011 s |
| features | 0.0016–0.0018 s | 0.0025 s |
| export | 0.003–0.005 s | 0.004 s |
| **TOTAL** | **0.032–0.040 s** | **0.063–0.074 s** |

**Qu is ~1.8–2x faster end to end.** No single stage dominates the gap the
way `read_csv` did in `csv_filters` before that fix — `load` is still the
biggest single contributor (Qu ~35% of its total, Python ~55% of its
total), but every stage is at least competitive.

**Correctness cross-checked, not just timed**: the extracted features
match closely between independently-generated datasets (different RNG
streams, so not bit-identical, but the same signal by construction) —
`mean_entropy` matches to 4 decimal places (0.1651 both), `n_peaks` matches
exactly (1 both), `rms`/`crest_factor`/`energy` all agree to 2-3 significant
figures. The Python `spectral_entropy` was hand-implemented (`scipy` has no
direct equivalent) to match Qu's own definition — Shannon entropy of each
STFT frame's normalized power spectrum, scaled to `[0,1]` by `log2(n_bins)`
— and the 4-decimal match confirms that port is faithful, not just
plausible-looking.

## Tests

No dedicated `#[ignore]`d test — same reasoning as `csv_filters`, a
same-language-pair timing comparison rather than an algorithm-correctness
check. The printed feature values (`rms`/`crest`/`energy`/`n_peaks`/
`mean_entropy`) in both scripts are the "did the pipeline actually compute
the right thing" check, confirmed matching above.
