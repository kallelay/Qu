Written for this form and run by the build -- the output below is what the engine actually produced.

How it works

The streaming (sample-at-a-time) filtering pair, for real-time/serial-fed data where a whole array isn't available up front: state = filter_init(filt) then repeatedly state = filter_next(state, next_sample), reading state.y for each filtered output — the same "thread a new state through each call" idiom kalman_predict/kalman_update already use, not a mutable iterator object (Qu has no mutation-of-shared-state primitive for this, by design). filter_init(filt) — a fresh all-zero state: an (n_sections, 2) biquad-state matrix for an IIR (sos) filter, or a len(b)-1-long all-zero delay line for an FIR (b) filter — simpler, since there's no feedback state to track at all, just the last few inputs.
