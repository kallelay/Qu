vstack

Builtin index · Core maths

result = hstack(a, b, ...)

Input: a, b, ... · Output: result

What it is

Named equivalents of bracket-literal block concatenation ([a, b] horizontally / [a; b] vertically). Each of the 2+ required arguments is a scalar, Vec, or Mat (real or complex — any complex argument makes the whole result complex); hstack needs matching row counts, vstack needs matching column counts.

Overloads

One call shape — this function is not overloaded.

Examples

From the documentation, and run by the build -- the output and the figure below are what the engine actually produced. Simplest first.

G = vstack(randn(40, 2, seed = 31) + 4,
           randn(40, 2, seed = 32) - 4,
           randn(40, 2, seed = 33))
labels = kmeans(G, 3, seed = 5)
centers = kmeans_centers(G, 3, seed = 5)
xs = G[:, 0]
ys = G[:, 1]
for k in 0 to 2
    inside = labels == k
    print("cluster {k}: {len(xs[inside])} points")
    scatter(xs[inside], ys[inside], label = "cluster {k}")
end for
scatter(centers[:, 0], centers[:, 1], marker = "x", color = "#0f172a", size = 12, label = "centroids")
legend()
title("kmeans, k = 3")

How it works

hstack(a, b, ...) / vstack(a, b, ...) — explicit, named equivalents of the bracket-literal block-concatenation magic ([a, b] / [a; b], see eval_matrix_literal_blocks), for scripts that would rather spell the operation out than rely on [...]'s implicit dispatch — same "also give it a plain function name" precedent as panel/subplot. Both need 2+ arrays; a single argument would make the call redundant.

From the note above this builtin in the interpreter, where the reasoning was written down as it was built.
