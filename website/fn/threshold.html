threshold

Builtin index · Images

result = threshold(x, level)

Input: x, level · Output: result

What it is

x is an Image, Signal, Vec, or scalar; level is a number, the cutoff. Elementwise binary threshold, general-purpose (not image-specific). Image → binary black/white image of the same dimensions (per-pixel BT.601 luma vs level); Signal → same-Fs Signal of 0.0/1.0; Vec/scalar → identical to x >= level (a Mask/Bool via the shared compare path).

Overloads

x can be Image, Signal, Vec, or number; level can be Image, Signal, Mask, Vec, bool, or scalar.

multithreshold branches on x's type the same way, but the results differ more: its Image case returns a posterized *image* (evenly-spaced gray bands), while its Signal/plain-numeric case returns a raw 0-based *band index* rather than anything image-shaped.

How it works

threshold(x, level) (§ thresholding, 2026-08-24, Ahmed: "Threshold & multithreshold should be implemented in signal too, [along with] Otsu method and better methods") — elementwise binary threshold. NOT the same job as foreground_mask above (that one is a blob/segmentation convenience — threshold + morphological opening in one call); this is the plain, general-purpose global threshold, with no morphology, usable on Image/Vec/Signal alike. Value::Image -> a binary black/white image (per-pixel BT.601 luma vs level, not three independently-thresholded channels — the standard convention ahead of segmentation, same luma computation foreground_mask/to_grayscale already use); Value::Signal -> a same-Fs Signal of 0.0/1.0; Value::Vec/scalar -> reuses the exact >= comparison operator's own output convention (a Mask for a vector, a Bool for a scalar) via compare, so threshold(x, level) and x >= level agree exactly on anything that isn't an Image/Signal. See apply_threshold's doc comment for the full rationale.
