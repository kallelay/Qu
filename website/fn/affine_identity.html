How it works

Real, composable geometric transforms unified through actual 3x3 homogeneous-coordinate matrices — Qu's OWN */matmul (already dispatching to Matrix::matmul at the matrix boundary — see binop/ matrix_binop above) composes them, not a separate composition mechanism invented for this feature. Convention (the one genuinely easy-to-get-backwards design decision here, pinned down by affine_composition_translate_then_rotate_... in this module's own test suite, below): a point transforms as M @ [x, y, 1]^T. Composing A = affine_translate(...) * affine_rotate(...) * affine_scale(...) and applying A @ p computes translate(rotate(scale(p))) — scale happens FIRST (the rightmost/innermost factor), then rotate, then translate LAST (the leftmost/outermost factor) — the same right-to-left application order as OpenGL's own M = T*R*S convention, not a Qu-specific choice. affine_rotate's matrix is the plain textbook CCW rotation matrix in a standard (x right, y up) coordinate system — deliberately NOT special-cased for image pixel coordinates (y increasing downward), unlike imrotate's own internal sign negation. Applied to image pixel coordinates via imwarp, a positive angle therefore appears CLOCKWISE on screen, not counterclockwise like imrotate — an intentional, documented consequence of keeping this builder mathematically general-purpose (usable for any point transform, not just images) rather than silently flipping its sign to match one particular downstream consumer.
