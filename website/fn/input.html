input

Builtin index · Statistics & ML

result = input(n)

Input: n · Output: result

What it is

Starts the pipeline sugar: n (a positive integer) is the number of input features.

Overloads

One call shape — this function is not overloaded.

CodeInputOutputDescription
result = input(n)
n numbernot documented yet
result Record
Returns a pipeline_input Record tracking the running output width and an (initially empty) layer list, ready to be piped into dense(...) stages and finished with compile(...).

How it works

style ergonomics over the raw param/dense/relu/grad primitives above, WITHOUT the spec's (§38.4) unbuilt model ... end model / layer ... end layer grammar. Every piece here is an ordinary function returning Value::Record (an unfitted layer spec) or Value::Model (an initialized network) — the same "fit-style API via existing value shapes, no new syntax" convention kmeans_model/fit_scaler/ gru_init already established. See sequential_forward's own doc comment for how a spec+params pair actually runs. input(n) — starts a Tier-2 pipeline (Sequential pipeline API, 2026-08-26): a lightweight Value::Record tagged kind = "pipeline_input" tracking just the running output shape (out_dim, starting at n) and the layer-spec list built so far (empty here). Every dense(...) pipeline stage (see that builtin arm's own doc comment) reads and extends this same shape via eval_pipe's "piped value becomes the first argument" rule, and compile(...) turns the finished Record into a real sequential(...) model. Deliberately a DIFFERENT Record shape from dense_layer's own pipe-chain accumulation just below (kind="dense"|"dropout", checked by is_layer_spec) — two independent, non-colliding pipe-based ways to build a layer list, not one competing with the other.
