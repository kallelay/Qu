findpeaks

Builtin index · Signal processing

findpeaks(x, [min_peak_height=], [min_peak_distance=])

Input: x, min_peak_height, min_peak_distance · Output: no output

What it is

x is a length-N vector; min_peak_height/min_peak_distance (optional numbers) as above. MATLAB-style [peaks, locations] = findpeaks(x, ...). Qu has no multi-return/tuple-unpacking assignment, so this returns a Model (kind "findpeaks") with fields peaks (a vector of the peak values), locations (a vector of their 0-indexed integer indices into x — not MATLAB's 1-indexing), prominences (a vector, one per peak, the real prominence value) and widths (a vector, one per peak, the width in samples at rel_height=0.5) — the same named-field convention qr/lu/svd/eig use. Shares its peak-finding/non-max-suppression logic with find_peaks above.

Overloads

One call shape — this function is not overloaded.

How it works

findpeaks(x, [min_peak_height=], [min_peak_distance=]) — MATLAB-style [peaks, locations] = findpeaks(x, ...). Qu has no multi-return/tuple-unpacking assignment (see the argmin/argmax/median/... doc comment history), so this returns a Value::Model instead, the same named-field multi-return convention qr/lu/svd/eig already use: kind "findpeaks", fields peaks (the values) and locations (their 0-indexed positions in x — Qu is 0-indexed everywhere, unlike MATLAB's 1-indexing, so there is deliberately no +1 offset here). Shares its actual peak- finding/non-max-suppression logic with find_peaks above (numeric::transforms::find_peaks) rather than a second implementation; min_prominence isn't exposed as a FILTER here since MATLAB's own findpeaks kwarg vocabulary this is modeled on is MinPeakHeight/MinPeakDistance, not prominence. Two more fields, prominences and widths (each one value per located peak, same order as peaks/ locations), are computed unconditionally via numeric::transforms::peak_prominence/peak_width (the real SciPy-style bounding-minima/interpolated-crossing algorithms, width at rel_height=0.5, "full width at half prominence") — this is the enriched alternative to find_peaks above for scripts that want the VALUES, not just filters on them.
