findpeaks

Builtin index · Signal processing

result = findpeaks(x, [min_peak_height=], [min_peak_distance=])

Input: x, min_peak_height, min_peak_distance · Output: result

What it is

x is a length-N vector; min_peak_height/min_peak_distance (optional numbers) as above. MATLAB-style [peaks, locations] = findpeaks(x, ...). Qu has no multi-return/tuple-unpacking assignment, so this returns a Model (kind "findpeaks") with fields peaks (a vector of the peak values) and locations (a vector of their 0-indexed integer indices into x — not MATLAB's 1-indexing) — the same named-field convention qr/lu/svd/eig use. Shares its peak-finding/non-max-suppression logic with find_peaks above.

Overloads

One call shape — this function is not overloaded.

How it works

findpeaks(x, [min_peak_height=], [min_peak_distance=]) — MATLAB-style [peaks, locations] = findpeaks(x, ...). Qu has no multi-return/tuple-unpacking assignment (see the argmin/argmax/median/... doc comment history), so this returns a Value::Model instead, the same named-field multi-return convention qr/lu/svd/eig already use: kind "findpeaks", fields peaks (the values) and locations (their 0-indexed positions in x — Qu is 0-indexed everywhere, unlike MATLAB's 1-indexing, so there is deliberately no +1 offset here). Shares its actual peak- finding/non-max-suppression logic with find_peaks above (numeric::transforms::find_peaks) rather than a second implementation; min_prominence isn't exposed here since MATLAB's own findpeaks kwarg vocabulary this is modeled on is MinPeakHeight/MinPeakDistance, not prominence.
