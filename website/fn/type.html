type

Builtin index · Collections & strings

result = type(x)

Input: x · Output: result

What it is

x is any value.

Overloads

One call shape — this function is not overloaded.

CodeInputOutputDescription
result = type(x)
x Str, number, string, vector, or matrixnot documented yet
result Str, number, string, vector, or matrix
Returns a Str: the value's type, e.g. "number", "string", "vector", "matrix", "table", "layer".

Examples

From the documentation, and run by the build -- the output and the figure below are what the engine actually produced. Simplest first.

words = ["banana", "apple", "cherry"]
print(sort(words))            # ("apple", "banana", "cherry") -- a List, lexicographic

nums = [3, 1, 4, 1, 5]
print(sort(nums))             # [1, 1, 3, 4, 5] -- a Vec, numeric

print(type(sort(words)))      # "list"

print(type(sort(nums)))       # "vector"

How it works

writeline is an exact alias of print; write is the same but without the trailing newline (Pascal/BASIC convention). type(x) -- the value's own type name, exactly the string this interpreter already puts in every "expected a number, found <type>" error message (Value::type_name). Added 2026-09-04 after finding there was NO type introspection in the language at all: a script could be handed a none, a string, a serial handle or a table and had no way to ask which it got, even though the engine names the type back at you the moment anything goes wrong. That asymmetry is the gap -- reusing type_name rather than inventing a second vocabulary means what a script reads and what an error message says can never drift apart.
