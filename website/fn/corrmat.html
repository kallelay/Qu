corrmat

Builtin index · Plotting

result = corr_heatmap(t)

Input: t · Output: result

What it is

Computes the pairwise Pearson correlation of Table t's numeric columns. corr_heatmap/corrplot render it directly as a heatmap and return nothing; corrmat(t) instead returns a tagged Model (.matrix, an n-by-n Mat of correlation values, plus .labels, a List of the n column names) for when you want the numbers rather than a picture — calling .plot() on that Model also renders the labeled heatmap.

Overloads

One call shape — this function is not overloaded.

How it works

data.corrmat() — the pairwise Pearson correlation matrix of data's NUMERIC columns only (text columns silently skipped, same filter corr_heatmap/describe already apply — a correlation of a text column isn't meaningful). Builds a samples-by-features Mat from those columns and delegates the actual computation to the existing corrcoef_matrix (landed at 85f1631 as the corrcoef(X) builtin) rather than a second copy of that math. Returns a Value::Model (kind="corrmat", fields matrix + labels), NOT a bare Value::Mat — so .plot() can recognize "this came from corrmat()" and render a labeled heatmap instead of falling through to the ordinary flattened-line-plot path an arbitrary Mat gets (see the "plot" arm below). The alternative from the spec — treat ANY square Mat with a diagonal of 1s as "must be a correlation matrix, render as heatmap" — was rejected: an unrelated square matrix that happens to have 1s on its diagonal (eye(n), a similarity/adjacency matrix, ...) would then silently misrender as a heatmap with no way to opt back into a normal plot. A Model tag can never collide with an unrelated value by accident, matching how kmeans/pca/ every other tagged-result builtin here already works.

From the note above this builtin in the interpreter, where the reasoning was written down as it was built.
