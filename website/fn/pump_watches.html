pump_watches

Builtin index · Concurrency

result = pump_watches()

Input: no input · Output: result

What it is

Takes no arguments. Checks every registered watch ... end (§ Watches, below) exactly ONCE, right now, against its real current external state, firing the body of any whose state has genuinely changed since the last check. Unlike run_for, this is real-time, not simulated — a file's mtime, a variable's value, and an HTTP response body have no "virtual" equivalent to fast-forward through. Requires at least one watch to already be registered, or it errors.

Overloads

One call shape — this function is not overloaded.

CodeInputOutputDescription
result = pump_watches()no input
result number
Returns an integer: the number of watches that fired on this call.

fires = 0
watch file("config.txt") do
    fires = fires + 1
end

touch("config.txt")      # real mtime bump (creates the file if missing)

f2 = pump_watches()      # -> 1

f3 = pump_watches()      # nothing changed since f2's check -> 0

How it works

pump_watches() (§ watch, 2026-09-01) — checks every registered watch ... end ONE TIME, firing the body of any whose real external condition (a file's mtime, a variable's value, an HTTP response body) has genuinely changed since the last check (or since registration, for the first call). Deliberately a SEPARATE function from run_for, not a mode of it, after investigating reuse first: run_for(duration) drives registered timers across a SIMULATED virtual clock with no real waiting (see its own doc comment) — there is no equivalent "simulated" file mtime, variable value, or HTTP response to fast-forward through, since a watch's condition is real external state that can only be checked for real, right now. Folding watches into run_for's duration-driven loop would either force every watch check to happen at some fabricated virtual timestamp that means nothing for a filesystem/HTTP check, or silently degrade into "check once at the start," neither of which is honest about what a poll-based watch actually does. pump_watches() instead means exactly what it says: check everything, right now, once — a script drives repeated checking itself (e.g. wait until ... sleep(…) ; pump_watches() ... end until), the same cooperative, explicitly-pumped model run_for already established, just without a duration parameter that would not mean anything here. Snapshots the registered-watch COUNT up front (n = self.watches.len(), matching run_for's own self.timers.clone() snapshot) so a watch registered by another watch's own body mid-pump is not itself checked until the NEXT pump_watches() call. Returns the number of watches that fired.
