fir1

Builtin index · Signal processing

result = fir1(n, cutoff, [kind="low"], [window="hamming"], [fs=2], [beta=])

Input: n, cutoff, kind, window, fs, beta · Output: result

What it is

n: number (order, taps = n+1); cutoff: number or length-2 vector; kind (optional string); window (optional string: "hamming", "hann"/"hanning", "blackman", or "kaiser" — the last needs beta=, a required number when chosen); fs (optional number, default 2.0, MATLAB's normalized convention where 1 = Nyquist) — pass an explicit fs= for butter-style Hz cutoffs.

Overloads

cutoff can be number or vector.

How it works

fir1(n, cutoff, [kind="low"], [window="hamming"], [fs=2]) — windowed-sinc FIR design (MATLAB's/SciPy's fir1): the ideal lowpass/highpass/bandpass/bandstop impulse response truncated to n+1 taps, multiplied by the requested window (reusing hamming/hann/blackman/kaiser's own Rust functions directly — raised_cosine_window/kaiser_window below — not reimplemented), normalized to unity gain at the passband center. kind accepts the same aliases as butter. fs defaults to 2.0, MATLAB's own *normalized* fir1 convention (cutoff directly in [0, 1], 1 = Nyquist — also fvtool's own existing fallback below); pass an explicit fs= for butter-style Hz cutoffs instead. Model kind "filter", field b (a plain tap vector) — no sos field at all, since an FIR filter has no feedback/denominator and can't be forced into a biquad cascade without first factoring its transfer-function polynomial into quadratic roots (a real numerical step this design function doesn't do). Every generic filter function below (sosfilt/ filtfilt/freqz/group_delay/fvtool/filter_init/ filter_next/poles/zeros/is_stable/pzplot) branches on whether a filter model has sos or b.
