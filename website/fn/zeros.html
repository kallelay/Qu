zeros

Builtin index · Core maths

zeros(n) / zeros(r, c)

Input: n · Output: no output

What it is

A vector or matrix of zeros. One numeric argument n gives a length-n Vec; two arguments r, c give an r×c Mat — even a degenerate two-argument shape like zeros(n, 1) stays a genuine oriented matrix, distinct from the plain Vec that zeros(n) returns. Overloaded by argument type: zeros(filt), where filt is a "filter" model (from butter/fir1/etc.), instead returns that filter's zeros as a CVec (see [Signal Processing & Filters](signal-processing.md)).

Overloads

n can be vector, matrix, Vec, Mat, CVec, or Signal; r can be Mat, matrix, or Vec; c can be Mat, matrix, or Vec; filt can be vector, matrix, Vec, Mat, CVec, Signal, or Model.

How it works

constructors: zeros(n)/zeros(r, c); a genuine 2-D shape gives a matrix, a single dimension (or a k x 1 / 1 x k) gives a vector. zeros(filt) -- overloaded on argument type, not a separate name: when the (sole) argument is a "filter" model, this is instead the filter's zeros (IIR: each section's b0*z^2+b1*z+b2=0 roots; FIR: the whole tap polynomial's roots via the companion-matrix eigenvalue method, reusing eig rather than a bespoke root-finder). Matches MATLAB's own zeros/tf2zpk naming without a second builtin name for the same concept poles(filt) already established.

From the note above this builtin in the interpreter, where the reasoning was written down as it was built.
