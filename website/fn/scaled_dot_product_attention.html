scaled_dot_product_attention

Builtin index · Statistics & ML

result = scaled_dot_product_attention(q, k, v, [mask=])

Input: q, k, v, mask · Output: result

What it is

Core attention computation: an (Nq, D) query matrix q, an (Nk, D) key matrix k, and an (Nk, Dv) value matrix v (k and v share the same row count Nk). Scores are q * kᵀ scaled by 1/sqrt(D) before the softmax, so the softmax does not saturate as D grows; an optional mask matrix (same shape as the score matrix, (Nq, Nk)) adds large negative values to positions that should not be attended to before the softmax.

Overloads

One call shape — this function is not overloaded.

How it works

scaled_dot_product_attention(q, k, v, [mask]) — softmax(Q K^T / sqrt(d_k)) V (Vaswani et al. 2017, eq. 1). q/k/v are (seq_len_q, d_k)/(seq_len_k, d_k)/ (seq_len_k, d_v) matrices (or Tensors wrapping them); an optional 0/1 mask of the raw scores' own (seq_len_q, seq_len_k) shape (1 = attend, 0 = block) is added as a large negative bias BEFORE the softmax — the standard "additive mask" convention, not zeroing probabilities after the fact (which would leave blocked entries still skewing the row's normalization). K^T uses tt (this session's new tracked transpose, so gradient flows back into k too); the two matmuls (Q@K^T, probs@V) reuse tb's "*", and so Matrix::matmul's own existing rayon parallelism above its size threshold — the actual CPU-parallel win for this op. True head-level parallelism (see multi_head_attention) can't extend down into this call too: every tracked op here mutates self.tape behind one shared &mut self.
