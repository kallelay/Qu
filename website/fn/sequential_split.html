sequential_split

Builtin index · Statistics & ML

result = sequential_split(X, y, [test_size=0.2])

Input: X, y, test_size · Output: result

What it is

The same shape as train_test_split on X/y/test_size, but never shuffles: the first rows become the training set, the last rows the test set, in their original order.

Overloads

One call shape — this function is not overloaded.

How it works

sequential_split(X, y, [test_size=0.2]) — the time-series- safe split: NO shuffling, ever. The first (1-test_size) fraction of rows (in original order) is train, the remainder is test. This exists as its own named builtin rather than just documentation telling a script to pass shuffle=false to train_test_split, because shuffling time-ordered data before splitting is a real, easy-to-miss correctness bug: once shuffled, "future" rows land in the training set, so a model trained on them can look artificially good on a test set that's secretly full of rows temporally *before* some of its training data — data leakage from the future, not just a style choice. Reusing train_test_split's shuffle=false path under a name that says "safe for time series" out loud is the point.
