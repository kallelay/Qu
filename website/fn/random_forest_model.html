random_forest_model

Builtin index · Statistics & ML

result = random_forest_model(X, y, n_trees, [max_depth=20], [seed=], [kind=])

Input: X, y, n_trees, max_depth, seed, kind · Output: result

What it is

Bagged ensemble of n_trees (a positive integer) CART trees on an N-row, D-column X and length-N y, each tree grown on its own bootstrap resample of the rows and a ceil(sqrt(D))-column feature subsample at each split, max_depth per tree (default 20), an optional integer seed= that reproducibly seeds every tree's own draw, and kind ("regression" or "classification", never inferred).

Overloads

One call shape — this function is not overloaded.

Examples

From the documentation, and run by the build -- the output and the figure below are what the engine actually produced. Simplest first.

Xc = randn(200, 2, seed = 41)
yc = zeros(200)
for i in 0 to 199
    if Xc[i, 0] + Xc[i, 1] > 0
        yc[i] = 1
    end if
end for
s = train_test_split(Xc, yc, test_size = 0.3, seed = 9)

function accuracy(model)
    yhat = model.predict(s.X_test)
    hit = yhat == s.y_test
    return len(yhat[hit]) / len(yhat)
end function

names = ("knn", "tree", "forest", "bayes")
scores = (
    accuracy(knn_model(s.X_train, s.y_train, 5, kind = "classification")),
    accuracy(tree_model(s.X_train, s.y_train, kind = "classification")),
    accuracy(random_forest_model(s.X_train, s.y_train, 40, seed = 3, kind = "classification")),
    accuracy(naive_bayes_model(s.X_train, s.y_train))
)
for i in 0 to 3
    print("{names[i]}: {round(scores[i], 3)}")
end for
bar(0 to 3, scores, color = "#4169e1", values = true)
xticks(0 to 3)
xticklabels(names)
ylim(0, 1)
ylabel("test accuracy")
title("held-out accuracy, same split")

How it works

random_forest_model(X, y, n_trees, [max_depth=], [seed=], [kind=]) — bootstrap-aggregated tree_models (see this match arm's own doc comment above for kind=). Each tree is grown on an independent bootstrap resample (n draws with replacement from the n training rows) AND a random feature subsample at every split (ceil(sqrt(d)) candidate features, sklearn's own classifier default, used for both kinds here for simplicity) — so both halves of "Random Forest" the backlog asked for ("bootstrap resampling required, feature subsampling nice-to-have") are actually implemented, not just the required half. seed= seeds one master Rng; each tree's own bootstrap draw AND feature subsampling draw a fresh seed off that master stream *before* that tree is built (the same "seeds drawn sequentially off the parent stream first" convention spawn/parallel for/the parallel-randn path all already use), so the whole forest is reproducible under one seed= yet no two trees share a stream.
