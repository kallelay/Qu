conv2d

Builtin index · Statistics & ML

result = conv2d(x, kernel, [stride], [padding])

Input: x, kernel, stride, padding · Output: result

What it is

Slides a (Kh, Kw) learnable kernel matrix over an (H, W) image matrix x, moving stride positions at a time (integer, default 1) with padding — "valid" (no padding) or "same" (output keeps x's (H, W) shape); default "valid".

Overloads

One call shape — this function is not overloaded.

How it works

conv2d(x, kernel, [stride], [padding]) — the 2-D sibling of conv1d above, picking up exactly the follow-ups that arm's own doc comment named as out of scope: real stride and "valid"/"same" padding. Still deliberately single input channel & single output channel (multi-channel is its own, larger follow-up — same "correct over broad" call). x is either a lone image (Value::Mat, H x W) or a batch of them (Value::List of Value::Mat, one image per element — List, not a stacked Mat, since a whole 2-D image can't be one row of another matrix the way a 1-D sequence could for conv1d's own batching). kernel is always a plain Mat (kH x kW). stride (positional 3rd arg or stride=, default 1) and padding (positional 4th arg or padding=, default "valid") are both optional, mirroring conv1d's own default-everything-else shape. The sliding-window sum itself runs on rayon (conv2d_single's into_par_iter over output rows) — real CPU-parallel acceleration, not "runs on one core under a fancier name." Gradient-checked against central finite differences for both x and kernel (lone image and batched-List, "valid" and "same") before this shipped, matching every other autodiff addition in this file.
